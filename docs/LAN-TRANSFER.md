# 设备互联传输与连接恢复

设备互联保留 `wenxi-lan-1` 协议、连接码、文件分享链接、收件箱、目录结构和 SHA256 校验。本次参考 [LocalSend](https://github.com/localsend/localsend) 的设备发现、HTTP 确认和主动流式传输思路，补充原有连接流程。源码参考版本为 `92e133aa43869e94d394fd04fa70c50a0f796a64`；未引入 LocalSend 的 Rust 核心或复制其实现，也不与 LocalSend 应用互通。

## 设备发现

开启互联依据本机的可用 IPv4 地址，不依赖外网连通性检测。支持 RFC1918 私网、`100.64.0.0/10` 共享地址和 `169.254.0.0/16` 链路本地地址；网卡枚举包含链路本地地址，Wi-Fi/以太网优先，虚拟网卡随后，链路本地地址最后。公网 IP 和域名仍不作为互联地址接受。共享网段也用于扫码、发现、HTTP 地址校验和文件邀请，配对授权规则保持一致。

视频可播放只说明外网可用，不能证明两台设备处于同一局域网。当前互联监听与发现仍使用 IPv4；仅有 IPv6 或没有可用本地地址时，提示“未检测到可用的局域网 IPv4 地址”，不会直接断言设备断网。`169.254` 可用于同一链路的设备，实际连接仍取决于路由和设备隔离。

地址读取、设备身份初始化、HTTP 监听和前台服务启动失败均记录对应阶段；没有可用地址时记录 IPv4/IPv6、过滤和网卡数量，读取或绑定异常保留数字错误码。端口被占用时回退到随机可用端口并记录。启动失败或取消后关闭资源、清除旧地址和连接码，可重新开启重新检测；日志不保存地址列表或网卡名称。

- 先发送原有 UDP 宣告，再优先探测已发现和曾连接的 HTTP 端点。
- `GET /v1/info` 确认协议、设备 ID 和端口；`POST /v1/discover` 交换公开的设备信息，让双方在 UDP 不通时也能发现对方。发现不会自动完成配对。
- 未找到可访问设备时补查本地 `/24` 子网，最多 508 个地址、12 个并发，每次探测总超时 650 毫秒。自动扫描间隔至少 60 秒；手动刷新可立即补查。
- 已知设备约每 9 秒探测一次。网络变化或关闭互联时取消探测；公网 URL、域名、连接码和会话凭据不进入发现缓存。
- 扫码、手动地址和多网卡候选地址继续核对设备 ID；不会把连接码发送给其他设备。

## 文件和消息通道

通常仍通过发送端 HTTP 读取文件。双方支持新能力时，主动配对方还会向对方建立经过会话验证的 `/v1/reverse` WebSocket。接收方无法回连发送端时，通过这条已经建立的连接反向请求分享清单、文件分片和消息。

下载组件访问本机 `/v1/receive/<随机标识>`，由本机选择直接 HTTP 或反向通道。两个通道均保留 `Range`、`If-Range`、ETag、内容长度和下载批次标识。文件流已经开始后不拼接其他响应；中断会关闭连接，让下载器重试对应分片。暂停后释放读取器，重新运行时重建本机入口，继续验证原断点和最终 SHA256。已完整下载的缓存可在设备互联关闭时继续校验和保存。

反向通道最多同时处理 16 个请求，每块最多 64 KiB；每块收到确认后才继续发送，防止慢速接收设备导致文件缓冲无限增长。断线后按 1、2、5、10 秒退避重连。直接连接失败后短暂记住可用通道，避免每个分片都重复等待不可达端点。

消息和配对仅对短暂网络错误及可恢复 HTTP 状态进行有限重试。消息保持同一个 ID，接收端同时核对发送者和内容；配对短期复用同一个响应，避免首次响应丢失后第二次请求使凭据失效。错误连接码和过期会话不会当成网络错误反复提交。

## 身份和兼容

会话继续绑定配对时确认的设备和源地址。分享邀请的地址仍必须属于实际发送设备。内部转发权限只允许真实本机请求使用随机许可，并核对当前会话；外部请求不能伪造转发头。反向请求只允许收件箱、分享列表、清单和文件路径。

旧版本不支持反向通道时继续走原有 HTTP 协议。新能力需要两端升级；重启后仍需按原规则重新配对，不能凭发现缓存自动授权。路由器开启设备隔离、两端均拒绝入站连接或 iOS 后台挂起时，仍需恢复网络或让应用回到前台。

日志新增发现、配对、重试和反向传输事件，以及连接数等诊断计数。不会记录连接码、会话凭据、文件名或完整分享链接。

## 浏览器互传

在客户端的设备互联中开启服务，使用「浏览器传文件」入口复制 HTTP 地址或显示网页二维码。同一局域网的浏览器打开地址，输入客户端的 6 位连接码即可发送文件和下载当前分享。网页二维码是普通 HTTP 地址，与客户端配对的 `wenxi://` 二维码分开。地址随当前网卡和监听端口变化，关闭互联或退出应用后失效；客户端关闭互联后仍可查看已完成的网页接收记录。

网页采用常规文件传输工具布局：左对齐页头、独立标签与输入框、明确的拖放区域，以及直接展开的发送队列和下载列表。连接信息在页头展示，使用系统字体、蓝色操作和跟随系统的深浅色主题。电脑并列显示发送与下载，手机单列显示，触屏显示文件选择提示，窄屏保留文件名换行和足够的按钮点击范围。HTML、CSS、脚本、增量 SHA-256 和图标均随应用打包，不需要公网服务、CDN、WebRTC 信令或另一台设备安装客户端。

手机接收文件沿用既定下载目录；电脑可在「网页接收记录」单独选择保存位置，不改变普通下载的默认目录。设置应用于之后准备接收的文件；现有传输保留其接收时确定的目录。接收复用 `FileAccess.save` 和下载管理器的 `SpaceBudget`，处理目录创建、平台 URI、同名自动编号、空间预留及取消保存。打开记录复用 `CompletedFileActions`，Android 将 `content://` 文档交给系统应用选择器，iOS 使用文件分享面板，电脑使用系统打开方式。

### 上传、恢复与清理

网页支持多文件选择、受浏览器支持的文件夹选择和电脑拖入文件。按队列顺序发送，先增量计算 SHA-256，再用不超过 2 MiB 的二进制分块上传。接收端完整收到并写入、flush 成功后才确认 offset；遇到响应丢失，网页先查询已确认的进度，再继续发送，避免重复拼接。每次最多缓存两个分块，未完成接收上限为 32 个文件，单个浏览器一次选择上限为 10000 个文件；网页队列最多显示 200 行。

上传中断后可重试。刷新页面后，浏览器无法自动保留本地文件句柄，需要重新选择原文件；客户端保留的 offset 和 SHA-256 用于续传及内容核对。接收完成先校验整文件，再保存到用户目录，完整校验和保存不依赖单次 HTTP 响应存活。保存失败保留完整暂存，可在客户端记录页重试保存；重复完成请求不会再次发布同一个文件。缓存被清理或修改时明确报错，无法通过校验的内容不会保存为成功文件。

取消、退出网页连接或关闭互联会停止对应接收、等待正在进行的工作结束并清理暂存。未完成且 30 分钟无活动的文件自动清理，网页连接 4 小时过期；应用重启清理其私有缓存目录中自身命名的 `.part` 文件。未完成任务不会跨应用重启恢复。最近 100 条成功记录随本地状态保留，清理传输缓存不删除已保存的用户文件。

### 下载与浏览器兼容

客户端创建的文件或文件夹分享出现在配对网页中。单文件交给浏览器原生下载，支持现有 `Range`/ETag 续传。多文件和文件夹使用流式 stored ZIP64，单次读取源文件并计算 CRC，保留 Unicode 路径、嵌套文件及明确的空目录；不会预生成整份临时 ZIP 或将大文件读入浏览器 Blob。ZIP 不提供断点续传，中断后需重新下载，进度、取消和保存位置在浏览器下载列表查看。

现代 Chrome、Edge 和 Safari 可使用普通文件选择与上传；文件夹选择取决于 `webkitdirectory` 支持，空目录不会由浏览器文件选择器提供，因此网页上传不创建空目录。手机浏览器切到后台可能暂停传输，恢复前台后重试；应用和浏览器都需要保持可访问。局域网 HTTP 无需 `showSaveFilePicker` 或 HTTPS `SubtleCrypto`，网页使用打包的增量 SHA-256。浏览器实际下载和平台文档权限仍需在目标设备检查。

### 网页授权与维护入口

匿名首页不显示连接码、私有文件名、分享清单或保存路径。网页配对沿用客户端的错误连接码频率限制；服务端创建独立的浏览器 owner 和 `HttpOnly; SameSite=Strict; Path=/web` Cookie，不复用客户端 Bearer 会话。网页路由核对本地地址、Host、同源请求、会话来源和有效期，浏览器不能凭自报 ID 取回其他连接的上传。授权后的状态仅包含该浏览器的接收任务，不返回本地保存路径；现有单文件完整分享链接继续按分享 token 授权。

服务使用局域网 HTTP，连接码用于访问控制，文件没有传输层加密。客户端和浏览器直接传输，不经过公网中继；应在自己信任的局域网使用。现有浏览器共享、配对和客户端协议继续各自管理生命周期。

主要实现位于 `lib/lan/lan_browser.dart`、`lan_browser_receiver.dart`、`lan_browser_zip.dart` 和 `lib/ui/lan_browser_panel.dart`，静态页面在 `assets/lan/`。首次网页请求加载打包资源；修改这些资源后需要重启服务进程验证。网页协议独立扩展到 `/web/session`、`/web/uploads` 及 `/web/zip`，原客户端 `/v1/` 协议保留。

2026-11-24 另参考以下公开实现的交互和流式处理思路，以本项目协议独立实现，未复制这些项目代码，也不与其应用互通：

- [LocalSend](https://github.com/localsend/localsend/tree/44f48f18a5503c43873570ff489d27ff1983e198)：网页共享、接收目录、授权和生命周期。
- [PairDrop](https://github.com/schlagmichdoch/PairDrop/tree/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77)：浏览器选文件、分块确认和进度反馈。
- [copyparty](https://github.com/9001/copyparty/tree/5a2d8e02137078eb97b0268c73ca8665307e1497)：二进制分块、已确认进度查询和续传处理。

网页布局另参考 PairDrop 的主要操作与设备状态分层、LocalSend 的网页上传入口和拖放反馈，以及 copyparty 直接展示文件列表的方式。仅参考交互和信息组织，沿用本项目页面、图标和协议实现。

## 验证

自动测试覆盖单向防火墙、无 UDP 发现、配对及消息响应丢失、反向连接重连、文件流截断、取消读取、乱序数据、错误范围、文件修改和分享结束。真实 Windows Gopeed 集成测试覆盖文件夹和空文件、暂停、接收端重启后的断点恢复、整文件 SHA256，以及旧 HTTP 任务兼容。

地址和启动回归另覆盖共享网段边界、链路本地地址枚举、物理/虚拟网卡顺序、扫码和 HTTP Host 校验、地址读取失败、取消、端口回退、前台启动失败后的重新开启。

网页回归使用 `test/lan_browser_test.dart`、`test/lan_browser_panel_test.dart`、`test/device_link_page_test.dart` 和 `test/download_location_picker_test.dart`，覆盖匿名隐私、Cookie/owner 隔离、分块重放、中断与并发、空间不足、取消/关闭、校验和保存重试、同名保留、缓存丢失、ZIP 解包、手机固定目录、电脑独立目录和二维码地址失效。`node --test tool/tests/lan-browser.test.cjs` 对照 Node SHA-256 校验 HTTP 网页使用的增量算法；真实浏览器另检查页面深浅色、窄屏、文件选择、刷新续传、网络中断及浏览器下载。

手机性能、实际路由器和跨平台双机环境仍需安装新版本实测，自动测试不代表固定的成功率或传输速度提升。
