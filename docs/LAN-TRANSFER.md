# 设备互联传输与连接恢复

设备互联保留 `wenxi-lan-1` 协议、连接码、文件分享链接、收件箱、目录结构和 SHA256 校验。本次参考 [LocalSend](https://github.com/localsend/localsend) 的设备发现、HTTP 确认和主动流式传输思路，补充原有连接流程。源码参考版本为 `92e133aa43869e94d394fd04fa70c50a0f796a64`；未引入 LocalSend 的 Rust 核心或复制其实现，也不与 LocalSend 应用互通。

## 设备发现

- 先发送原有 UDP 宣告，再优先探测已发现和曾连接的 HTTP 端点。
- `GET /v1/info` 确认协议、设备 ID 和端口；`POST /v1/discover` 交换公开的设备信息，让双方在 UDP 不通时也能发现对方。发现不会自动完成配对。
- 未找到可访问设备时补查本地 `/24` 子网，最多 508 个地址、12 个并发，每次探测总超时 650 毫秒。自动扫描间隔至少 60 秒；手动刷新可立即补查。
- 已知设备约每 9 秒探测一次。网络变化或关闭互联时取消探测；公网 URL、域名、连接码和会话凭据不进入发现缓存。
- 扫码、手动地址和多网卡候选地址继续核对设备 ID；不会把连接码发送给其他设备。

## 文件和消息通道

通常仍通过发送端 HTTP 读取文件。双方支持新能力时，主动配对方还会向对方建立经过会话验证的 `/v1/reverse` WebSocket。接收方无法回连发送端时，通过这条已经建立的连接反向请求分享清单、文件分片和消息。

下载组件访问本机 `/v1/receive/<随机标识>`，由本机选择直接 HTTP 或反向通道。两个通道均保留 `Range`、`If-Range`、ETag、内容长度和下载批次标识。文件流已经开始后不拼接其他响应；中断会关闭连接，让下载器重试对应分片。暂停后释放读取器，重新运行时重建本机入口，继续验证原断点和最终 SHA256。已完整下载的缓存可在设备互联关闭时继续校验和保存。

反向通道最多同时处理 16 个请求，每块最多 64 KiB；每块收到确认后才继续发送，防止慢速接收设备导致文件缓冲无限增长。断线后按 1、2、5、10 秒退避重连。直接连接失败后短暂记住可用通道，避免每个分片都重复等待不可达端点。

消息和配对仅对短暂网络错误及可恢复 HTTP 状态进行有限重试。消息保持同一个 ID，接收端同时核对发送者和内容；配对短期复用同一个响应，避免首次响应丢失后第二次请求使凭据失效。错误连接码和过期会话不会当成网络错误反复提交。

## 身份和兼容

会话继续绑定配对时确认的设备和源地址。分享邀请的地址仍必须属于实际发送设备。内部转发权限只允许真实本机请求使用随机许可，并核对当前会话；外部请求不能伪造转发头。反向请求只允许收件箱、分享列表、清单和文件路径。

旧版本不支持反向通道时继续走原有 HTTP 协议。新能力需要两端升级；重启后仍需按原规则重新配对，不能凭发现缓存自动授权。路由器开启设备隔离、两端均拒绝入站连接或 iOS 后台挂起时，仍需恢复网络或让应用回到前台。

日志新增发现、配对、重试和反向传输事件，以及连接数等诊断计数。不会记录连接码、会话凭据、文件名或完整分享链接。

## 验证

自动测试覆盖单向防火墙、无 UDP 发现、配对及消息响应丢失、反向连接重连、文件流截断、取消读取、乱序数据、错误范围、文件修改和分享结束。真实 Windows Gopeed 集成测试覆盖文件夹和空文件、暂停、接收端重启后的断点恢复、整文件 SHA256，以及旧 HTTP 任务兼容。

手机性能、实际路由器和跨平台双机环境仍需安装新版本实测，自动测试不代表固定的成功率或传输速度提升。
