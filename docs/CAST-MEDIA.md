# 投屏声音与字幕处理（2026-11-15）

## 反馈与已确认的缺陷

用户反馈另一个视频在手机正常播放，投屏后有画面但没有声音和字幕。这次不是旧报告中的 5.10 GB MKV。现有日志仍属于上次连接失败，没有这次视频的音轨、字幕轨道或电视静音状态，因此不能据此确认本次音频编码不兼容，也不能声称本次无声已彻底修复。

随后上传的 2026-11-15 13:56 日志确认视频源准备成功，但 Play 控制响应异常后立即关闭；本轮补充修复见 [CAST-NETWORK.md](CAST-NETWORK.md)。该日志仍未证明电视成功播放，声音和字幕处理继续保留，等待实际成功投屏后的验证。

代码确认原投屏只发送原视频地址：`SetAVTransportURI` 的 DIDL 没有外挂字幕信息，中转没有字幕路径，也没有 `GetMute` / `SetMute`。本机播放器选择的音轨或字幕不会改变电视读取的原文件内容。

## 本次实现

- 将已选的本地或同目录外挂字幕转换为 UTF-8 SRT，支持 SRT、WebVTT、ASS、SSA，以及 UTF-8 / 带 BOM 的 UTF-16。保留文字、多行和时间校正；ASS 样式与绘图不会烧录到视频。
- 字幕输入与输出各最多 8 MiB，最多 100000 条，转换在独立 isolate 执行。读取过程中再次限制字节数并设空闲超时，转换后的字节不可修改，也不依赖本机字幕临时文件生命周期。
- 字幕和视频由同一个局域网监听器提供，各会话使用随机路径。字幕响应支持 GET、HEAD、范围读取和 416；字幕 URL 不包含网盘 Cookie 或原始取链参数，也不接受远程账号字幕地址直接发送到电视。
- 视频资源仍排在 DIDL 的首项，附加字幕资源、Samsung `CaptionInfo` / `CaptionInfoEx`、PV 字幕属性及对应 HTTP 响应头。字幕使用与视频相同的本机地址和端口。
- 自动下一集或首次投屏遇到正在加载的匹配字幕时，最多等待 3 秒，取消投屏立即结束等待。慢字幕或转换失败不阻止视频投屏，并提示完成后重新连接。切集清理旧字幕，重连及失败后恢复原会话时重新发送该会话字幕。
- 增加电视静音状态读取及静音按钮。开始投屏保留电视原音量与静音；用户主动调高电视音量时，若已确认电视静音且支持控制，再解除静音。减小音量不解除静音。
- 可选 `GetMute` 查询使用整个请求最多 2 秒的预算；不支持、超时或返回无效状态后停止反复查询，不影响视频、进度或音量功能。静音控制失败不撤销已成功的音量变化。
- DIDL 和界面描述原文件默认音轨；没有默认标记时参考首个音轨，不把手机选中的音轨伪装成重新封装后的文件。
- `cast.media_tracks` 记录原音轨和选中音轨的编码、声道、采样率、轨道数量，以及外挂字幕是否已附加、条目数；`cast.mute_state` / `cast.mute_changed` 记录静音状态。中转请求区分字幕和媒体，字幕请求不会计入电视已读取视频的判断。日志不记录音轨标题、字幕文字或字幕地址。

## 保留的限制

- 目前仍发送原视频字节，没有实现音频转码、内嵌字幕提取或字幕烧录。电视接收器必须支持该视频的音频和内嵌字幕格式；手机能正常解码不能证明电视能解码。
- DIDL 中附加字幕表示已向电视提供字幕路径，不等于电视已显示字幕；部分接收器还需要在电视字幕菜单开启，也有接收器不支持这些扩展。
- 投屏开始后再次选择字幕、调整字幕延迟或关闭字幕，需要重新连接电视同步。当前不会自动重设电视媒体，避免擅自打断进度或改变暂停状态。
- 传统 GBK 等未支持编码会显示转换失败提示，不发送乱码字幕。SRT 保留基础文字，不保留 ASS 排版、动画或图形效果。
- Android 当前精简播放器库不包含音频 AAC 编码器及所需输出封装器，不能直接靠设置 libmpv 编码参数完成转换。本机测试用播放器支持范围不能当作 Android 产品支持范围。

## 验证范围

使用模拟 DLNA 接收器验证字幕元数据、静音控制与不支持时的处理；真实本机 HTTP 读取核验字幕和视频字节、请求范围、凭据隔离与会话关闭。播放器控制器测试覆盖自动下一集字幕等待、慢字幕、取消、重新连接、字幕关闭、读取失败和日志脱敏；原有外部播放器及分片中转测试继续运行。

没有连接反馈用户的电视，也没有拿到本次无声视频。下一步需用该视频与电视确认是否静音、实际使用的音轨和字幕编码，以及电视是否读取外挂字幕路径，之后再确定兼容转换的必要范围。
