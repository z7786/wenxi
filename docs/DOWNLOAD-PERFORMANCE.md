# 下载与删除的性能优化

2026-10-29。

下载进度每约 350 毫秒更新一次。旧实现每次从 JSON 重新解析整条下载记录，包括来源、请求头和检查点；下载页还重复按时间、状态排序。删除记录虽然已有分组提交，但后台每清理一个任务仍分别提交原生移除标记和缓存移除标记，逐次加密、刷新整个本地状态文件。勾选删除已保存文件时，也会逐条提交记录。

## 调整

- 进度、速度和阶段更新直接复制任务，保留不变的来源和检查点对象；状态及来源变更继续使用原解析规则。进度未变化时减少界面通知，工作连接数变化仍立即通知。原有进度保存周期保持不变。
- 缓存任务的创建时间顺序，仅新增、删除或重新导入时重排。每次读取仍返回独立列表，包含最新状态；界面按状态分组，保持组内时间倒序。
- 没有活动写入的任务，每最多 64 项合并删除记录与清理标记的提交。真实文件仍逐项删除；失败保留记录和原路径，取消会完成当前项并保留后续项。
- 原生和缓存清理成功后，每最多 64 项合并确认。失败项及清理期间新增的标记保留；关闭应用时提交已完成的不足一组部分。冷启动清理已有原生标记也只提交成功项。

取链、线程配置、网盘限制、文件校验、暂停续传和边下边播沿用现有流程。正在写入的任务仍先停止写入，再提交删除；只移除记录时保留已保存文件。选中删除文件但状态写入失败时，记录保持可重试，重复删除已不存在的文件不会误删其他文件。

## 本地对比

在 Windows Flutter 测试进程中，用 512 条历史记录、真实加密状态文件和临时文件测试；原生调用为本地模拟，无网盘请求或真实账号。两版使用相同测试脚本及数据。
