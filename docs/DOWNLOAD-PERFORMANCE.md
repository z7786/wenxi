# 下载与删除的性能优化

## 电脑端每批下载选择保存位置

电脑端“我的 → 下载设置”新增“下载前询问保存位置”，默认关闭。开启后，网盘单文件、多选、文件夹和播放器下载在新建任务前选择一次目录；同批文件共用该目录并保留子目录结构。文件操作菜单中的“下载到…”可直接选择目录，不受开关影响。直链/ED2K 对话框与 BT 文件选择页内嵌目录控件，不重复弹窗。

手机端继续使用原有设置的下载目录，不显示新增开关、“下载到…”菜单或直链/BT 内的目录控件；即使导入了开启询问的电脑配置，也不会弹出目录选择。

电脑端目录选择支持系统目录、当前默认目录、最近 5 个目录及系统浏览。“设为默认目录”仅在勾选并成功创建任务后生效；BT 页在目录下拉菜单中提供此选项。取消选择或任务入队保存失败不更改默认目录和历史。普通选择仅影响本批任务，继续、失败重试和应用重启沿用任务记录中的目录。后台更新和已自行选目录的局域网接收沿用原流程。

复用现有系统目录授权、缓存位置及保存校验；目录失效或权限不足由下载任务报告，不静默改存其他位置。默认目录、最近目录和新任务在同一次状态提交中保存。安装包与各平台系统目录选择体验通过 GitHub 构建后验收。

## Windows 虚拟盘路径兼容

部分 ImDisk 内存盘支持正常读写，但拒绝 Dart `resolveSymbolicLinks()` 使用的 Windows 最终路径查询，返回 `ERROR_INVALID_FUNCTION`（1）。这会在下载前的空间规划阶段被误报为存储或权限故障，见 [issue #92](https://github.com/z7786/wenxi/issues/92)。

空间规划、缓存校验、下载结果校验、保存及已完成文件复制/移动统一使用存储路径解析。先执行原生路径解析；仅在 Windows 返回“不支持”错误（1 或 50），且逐级检查确认所有路径组成部分都存在、没有符号链接/目录联接/其他重解析点时，使用规范化绝对路径。权限不足、路径不存在、元数据检查失败仍报错；能够解析的真实链接继续按实际目标校验。原有空间预留、同盘硬链接、跨盘复制及取消保护沿用现有流程。

模拟虚拟盘查询错误的回归覆盖下载、保存、缓存清理、同名保护和链接越界拒绝；实际 ImDisk 驱动与文件系统组合仍需 Windows 安装包验证。

## 天翼大文件下载校验与重试（2026-11-15，待编译）

Windows 实际下载一个 2 GiB 文件时复现最终 MD5 不匹配。与独立校验通过的完整下载逐字节对照后，发现 143 处服务器存储错误 XML，均出现在已传输部分文件内容之后。天翼节点保持 206 和正确的 Content-Range，随后提前结束；旧实现将错误 XML 写入文件并计入续传偏移，重试补齐长度后仍会校验失败。分享返回的 MD5 与附带校验文本一致，Dart 流式校验也能正确处理 2 GiB 及更大文件。

天翼下载响应新增 8 KiB 尾部保留窗口。仅在响应未达到请求长度且末尾包含已确认的 `GetObjectFailedInCoordinator` 错误 XML 时丢弃错误尾部，以正常网络中断进入既有重试流程；有效数据保留原位置和进度。完整响应、普通 XML 文件及一般网络中断不改内容，其他网盘不启用该窗口。不调整连接数、超时和重试上限，不关闭最终摘要校验。

通用超时读取使用自己持有的复用缓冲，读取成功后才复制到下载 worker 的缓冲。超时响应停止复用，防止迟到的读取覆盖下一次请求数据。每个响应只复用一份缓冲，没有逐次读取分配。

校验失败保留失败文件直到用户重试，清除可复用的完成标记和远端身份。单条重试、批量继续和全部继续兼容旧版错误记录，重新获取来源后丢弃损坏分片，保留任务 ID、目录和参数；普通网络中断和仅保存失败仍保留可用分片。损坏文件继续禁止保存，日志记录算法、期望/实际字节数及摘要短指纹，不记录账号、文件名或签名下载地址。

本地验证涵盖迟到读取覆盖、带末尾数据的 EOF、错误 XML 跨缓冲边界、错误尾部清除后的续传位置、重试用尽后的有效进度、完整 XML 文件、普通中断，以及新旧校验失败任务的单条/批量重试。六组下载与天翼相关测试共 221 项通过，Go 分片范围、慢尾段、百度和迅雷相关回归通过。

同一实际 2 GiB 文件在修复后以默认 64 连接通过完整 DownloadManager 下载、MD5 校验和 Windows 保存流程，状态为已完成，字节数为 2,147,483,648，总耗时 394 秒（含校验与保存）。未调整正式下载参数，未编译安装包或上传代码。临时账号凭据、签名下载地址与大文件在验证后清理。

## 2.2.5 校验与保存收尾（2026-11-08）

- 安卓直接下载目标的 MD5、SHA-1、SHA-256 校验在原生 IO 工作线程完成，复用 256 KiB 缓冲，通过已授权文件描述符定位读取，避免逐块跨平台传输后在界面线程计算。每次读取前检查取消，完成后再次验证目录访问、当前凭据和文件长度；校验退出后才允许释放文件描述符。
- 活动下载凭据缓存目标元数据，避免每次定位读写重读目标日志。发布状态必须成功写入原子日志后才更新缓存；文件同步、发布前日志、发布后日志和完成记录保存次序保持不变。
- 等待校验及开始校验只更新界面，完整文件已就绪和已保存文件路径仍持久化。完成状态保存成功后释放校验队列，再等待缓存与目标凭据清理，减少后续文件的排队时间。
- 旧安卓缓存任务导出缓冲由 64 KiB 调整为 256 KiB，保留逐块取消和进度检查。桌面同盘链接、跨盘复制及 iOS 文件提供者保存路线沿用原实现。
- `download.saved` 日志增加 `verifyMs` 和 `postQueueMs`，与已有 `saveMs` 分开记录。已有日志的保存耗时不包含此前校验和排队，不能直接作为此次提速对比。

## 调整

- 进度、速度和阶段更新直接复制任务，保留不变的来源和检查点对象；状态及来源变更继续使用原解析规则。进度未变化时减少界面通知，工作连接数变化仍立即通知。原有进度保存周期保持不变。
- 缓存任务的创建时间顺序，仅新增、删除或重新导入时重排。每次读取仍返回独立列表，包含最新状态；界面按状态分组，保持组内时间倒序。
- 没有活动写入的任务，每最多 64 项合并删除记录与清理标记的提交。真实文件仍逐项删除；失败保留记录和原路径，取消会完成当前项并保留后续项。
- 原生和缓存清理成功后，每最多 64 项合并确认。失败项及清理期间新增的标记保留；关闭应用时提交已完成的不足一组部分。冷启动清理已有原生标记也只提交成功项。

取链、线程配置、网盘限制、文件校验、暂停续传和边下边播沿用现有流程。正在写入的任务仍先停止写入，再提交删除；只移除记录时保留已保存文件。选中删除文件但状态写入失败时，记录保持可重试，重复删除已不存在的文件不会误删其他文件。

## 下载目录被清理后的恢复

Windows 在空间预检时查询现存父目录，开始下载及保存时递归补建所选目录。Android 的直接下载与旧缓存任务保存共用目录恢复入口：所选本地目录被删除后，优先通过仍有效的上级目录授权补建原路径；没有上级授权时，仅在原授权有效且系统允许原路径创建的情况下补建。默认下载继续使用 MediaStore 或旧系统的目录创建流程。

恢复只处理目录，不替换同名文件、不改存其他位置，也不重建断点记录中已丢失的文件。仅系统外部存储提供者的路径型文档 ID 可映射到本地路径，其他提供者的 ID 不作路径解析。存储卷离线时提示连接后重试；系统删除目录时撤销授权且无可用上级授权时，提示在下载设置中重新选择原目录。
