# 本地明文存储与旧版迁移

新版账号、设置、播放记录和下载任务使用应用私有数据目录中的 `state-v2.json`，保存明文 JSON、格式标识和 SHA-256 完整性校验。新安装不创建或访问系统密钥。保存时先写入并刷盘 `.tmp`，再将上一份完整数据留为 `.bak`，最后发布新文件；相同数据不重复写入，序列化和校验在后台 isolate 进行。

升级时先检查新版文件。新版主文件损坏可从有效临时文件或备份恢复；所有新版副本均不可读时进入恢复页，避免恢复过时的旧版账号。只有不存在新版文件时才读取 `state-v1.enc` 及其副本，使用原来的密钥解密并验证，再写入、刷盘、重新读取新版文件。旧加密文件和旧密钥保留，不覆盖下载引擎的存储代次或原密钥。

旧 Android Keystore、私有双份密钥文件、Windows DPAPI 和 Credential Manager 仅用于读取旧数据。旧密钥无法读取时保留原文件并进入恢复页，不清空账号、不创建覆盖旧数据的新密钥。旧密码保护恢复和旧加密账号备份仍可导入。已经丢失且没有副本、密码保护或备份的旧密钥无法重建。

Gopeed 的 `gopeed.db` 在单个 bbolt 事务中将旧 AES-GCM 值转换为明文 JSON，完成后写入格式版本 2。转换任一值失败则整个事务回滚，原任务、可读范围、请求头、BT 来源状态和断点保持。新版数据库重启不依赖密钥。Android 原生凭据写入私有明文 SharedPreferences，并保留旧记录读取和删除标记，防止退出后重新出现旧账号。

导出和备份可选择明文或密码加密，本地状态格式保持不变。明文使用 `asterlink-backup-v2` + SHA-256；设置密码时使用既有 `asterlink-backup-v1`、PBKDF2-HMAC-SHA1（210000 轮、随机盐）和 AES-256-GCM，密码至少 6 位，界面要求二次确认。密码不保存，遗忘后无法解密；WebDAV 登录密码和备份密码相互独立。旧 `asterlink-backup-v1` / `wenxi-backup-v1` 与旧 v2 文件继续可导入。账号分类包含 Cookie 和令牌，备份应作为账号资料保存。诊断日志继续脱敏，不将账号存储文件打包为普通日志。

## 分类手动备份与恢复

“我的 → 备份与数据 → 导出备份 / 恢复备份”进入统一页面，顶部切换备份与恢复，保存位置分为本地文件和网盘。WebDAV 在网盘列表中连接并管理，备份与恢复选择对应账号和目录。手机使用单列卡片，电脑宽屏分为内容与保存选项两栏；主操作固定在底部，键盘弹出时仍可访问。内部 `classifiedVersion: 1`，含创建时间、应用版本、快照 ID、账号引用与分类内容。整个文件最多 16 MiB，所有分类从一次状态快照读取。当前实现手动备份与恢复；自动计划、轮换保留和多设备同步不在此阶段。

- 应用设置：通用、下载、浏览与界面参数，排除 `destination`。恢复保留本机目录与背景。
- 外观设置：透明度、模糊等参数；所有新建本地导出、WebDAV 和网盘备份均不包含背景图片或图片引用。旧备份中的图片仍按原有完整性规则读取。
- 网盘账号：用户主动勾选分类及具体账号；仅导出选中的凭据和允许迁移的账号秘密。
- 收藏：网盘、分享收藏、文件夹分类与排序；无账号凭据也可单独备份和恢复。
- 播放数据：全局偏好、隐私开关、云端与 BT 记录，含关联的种子元数据。排除本地文件路径和下载任务引用；目录级偏好及可重建视频信息不迁移。
- 搜索配置：网盘排序、禁用列表、支持项优先与无痕偏好。
- 解析与搜索历史：解析记录、资源搜索词、账号/空间范围的网盘搜索词；排除规则缓存、临时权限、传输队列和日志。

恢复先验证并预览分类、数量和账号关联。未选分类保留；收藏按绑定后的稳定标识合并并保留已有名称/置顶，播放记录按修改时间合并，不取最大进度。设置更新所选分类。账号默认保留现有登录状态，可以选择替换；不按昵称合并。旧版 `legacy-*` 账号编号不能证明跨设备身份，使用导入凭据生成稳定的独立编号，或由用户明确绑定本机账号。未登录账号的收藏、云端播放与网盘搜索记录保存在 `backupPending`，可在同页“待关联账号的数据”中绑定后使用，也会继续包含在对应分类的导出中。

最终恢复通过 StateStore 单次受保护提交并回读。提交前验证失败、取消或写入失败不发布半个分类。应用状态内的 `backupUndo` 保存最近一次恢复涉及字段的原值和图片内容，在同一次提交中写入，因此重启后仍可“回退上次恢复”。它属于本地明文数据；回退会覆盖恢复之后对这些分类的编辑。账号恢复和回退都会推进凭据 revision。背景资产先在草稿保护下校验，提交失败后清理新资产；回退图片自包含，不依赖已被清理的背景文件。

## 远程备份可靠性

每次备份使用唯一文件名 `asterlink-backup-<时间>-<UUID>.json`。先上传包，完整回读对比大小与 SHA-256，再上传并回读 `.json.complete` 清单；界面不会把入队成功显示为备份成功。默认只列带完成标记的版本，恢复时再次验证清单与文件。勾选“显示旧版或未确认文件”可导入没有清单的文件，仍需验证包内完整性/密码。旧成功版本不被覆盖或自动删除。

WebDAV 在“网盘”列表中提供多账号连接，账号身份由服务器根目录与用户名共同确定。连接页保存前执行只读目录验证，“测试目录读写”单独执行真实写入、回读与删除随机对象；只读账号仍能浏览与恢复。登录密码默认仅在本次运行中使用，重启后重新连接；主动勾选“记住登录密码”后以明文保存在本机，导出账号分类时可设置备份密码加密。既有 WebDAV 配置用于预填连接地址与用户名，旧版未完成备份仍可输入密码继续。

网盘浏览通过 PROPFIND 读取目录，支持 MKCOL 新建文件夹、流式 PUT 上传、MOVE 改名/移动和 DELETE 删除；上传及移动保护同名文件。正常验证服务器证书，拒绝携带凭据跟随重定向；请填写最终存在的目录地址，不支持自签名证书绕过。读取目录和备份文件均限制大小，上传复用请求取消、写入状态及连接并发控制。文件下载通过带随机访问标识的本机回环代理转发 GET/HEAD 与 Range，请求凭据保留在内存中，不写入下载任务或原生断点；移除账号即撤销对应访问。需要网络数据时重新解析原账号和文件，避免重启后使用旧代理地址；未记住密码需重新连接，登录信息修订后旧任务按现有账号隔离规则要求重新选择文件。

网盘目录选择复用浏览器，保存具体账号、空间与目录 ID；WebDAV 另外保存服务器根目录，防止改动连接地址后将旧备份位置指向其他服务器。账号选择与目录页面显示对应网盘图标，按连接器能力判断可上传位置。普通网盘备份上传复用 UploadManager，读取复用 CloudRepository 的新鲜下载凭据及有限大小下载；下载清理租约按现有生命周期释放，目录列表遍历分页。WebDAV 备份借用已登录连接，读取、上传与旧任务修复复用同一协议客户端，关闭备份位置不会关闭网盘连接。部分网盘有容量、权限或非媒体下载限制，真实账号需另行验收。

远程备份先写入应用数据目录 `backup-staging`，状态 `backupTransfers` 保留文件名、摘要和目标，不保存备份密码/临时下载链接。失败、取消或重启后，可从“未完成的远程备份”继续同一个包；网盘已有任务沿用队列重试。远端已存在相同对象时先回读，防止重复上传；WebDAV 中断后留下的同名不完整包可重新 PUT，但带完成标记的版本不允许覆盖；网盘同名损坏对象提示放弃并新建版本。放弃会停止对应任务并移除本机暂存，保留远端对象；成功后清理暂存。备份列表中完成标记只是索引，不是密码验证或内容校验的替代。

新设备恢复远程备份时，先在网盘列表登录存放备份的账号，包括 WebDAV，再在恢复页选择目录和版本；版本列表提供加载、空目录和失败重试反馈，下载校验后预览分类，确认后才写入。本地文件恢复始终可用。启动故障页也支持新的分类包，恢复其中全部已知分类。

首次升级请直接覆盖安装，保留应用数据。版本包名、签名及下载目录保持一致。验证覆盖新安装、旧版本迁移、多次重启、迁移中断、损坏文件、错误旧密钥、未来数据格式、原下载断点、密码恢复与备份原子导入。
