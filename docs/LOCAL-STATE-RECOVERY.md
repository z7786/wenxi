# 本地明文存储与旧版迁移

新版账号、设置、播放记录和下载任务使用应用私有数据目录中的 `state-v2.json`，保存明文 JSON、格式标识和 SHA-256 完整性校验。新安装不创建或访问系统密钥。保存时先写入并刷盘 `.tmp`，再将上一份完整数据留为 `.bak`，最后发布新文件；相同数据不重复写入，序列化和校验在后台 isolate 进行。

升级时先检查新版文件。新版主文件损坏可从有效临时文件或备份恢复；所有新版副本均不可读时进入恢复页，避免恢复过时的旧版账号。只有不存在新版文件时才读取 `state-v1.enc` 及其副本，使用原来的密钥解密并验证，再写入、刷盘、重新读取新版文件。旧加密文件和旧密钥保留，不覆盖下载引擎的存储代次或原密钥。

旧 Android Keystore、私有双份密钥文件、Windows DPAPI 和 Credential Manager 仅用于读取旧数据。旧密钥无法读取时保留原文件并进入恢复页，不清空账号、不创建覆盖旧数据的新密钥。旧密码保护恢复和旧加密账号备份仍可导入。已经丢失且没有副本、密码保护或备份的旧密钥无法重建。

Gopeed 的 `gopeed.db` 在单个 bbolt 事务中将旧 AES-GCM 值转换为明文 JSON，完成后写入格式版本 2。转换任一值失败则整个事务回滚，原任务、可读范围、请求头、BT 来源状态和断点保持。新版数据库重启不依赖密钥。Android 原生凭据写入私有明文 SharedPreferences，并保留旧记录读取和删除标记，防止退出后重新出现旧账号。

新导出备份格式为 `asterlink-backup-v2`，使用明文及 SHA-256 校验，不再询问密码；导入旧 `asterlink-backup-v1` / `wenxi-backup-v1` 时继续询问原密码。新备份包含账号 Cookie 和令牌，应作为账号资料保存。新格式仅供新版应用导入，旧版应用不支持该格式。诊断日志继续脱敏，不将账号存储文件打包为普通日志。

首次升级请直接覆盖安装，保留应用数据。版本包名、签名及下载目录保持一致。验证覆盖新安装、旧版本迁移、多次重启、迁移中断、损坏文件、错误旧密钥、未来数据格式、原下载断点、密码恢复与备份原子导入。
