# Android 播放无响应退出排查（2026-11-16）

本次检查 `logs/文析助手-logs-2.3.5-235-1794828620301187.zip`。导出时应用是 2.3.5+235，但包内 8 次播放加载均来自 2.3.1+231；2.3.5 的会话开始于北京时间 19:29:21，仅有启动、页面操作和导出日志，没有播放记录。设备报告为 HONOR LDY-AN00、Android 17 / API 37。

## 能直接确认的问题

- 系统在 18:55:37 记录触摸分发超时，等待 5 秒仍未响应，18:55:41 记录 ANR 退出。主线程停在 `pthread_cond_wait`，后续原生栈偏移包括 `0x003ec304`、`0x00406160`。
- 用同一 2.3.1 ARM64 安装包的 `libmpv.so` 核对导出符号与反汇编，`mpv_get_property_string` 起点是 `0x0040611c`；`0x00406160` 是该函数调用内部等待函数的位置。状态采样每两秒调用同步 FFI 读取，外层返回 `Future` 和读取间主动让出事件循环，都不能中断单次原生等待。
- 本次播放为 HEVC、3840×1600、25 fps，实际使用 `mediacodec` 硬解。切换片源时出现两次 `acquireLatestImage failed: -30001`，随后恢复首帧并继续播放约 15 分钟，不能把这两条已恢复的错误直接等同于 ANR 原因。日志不能证明底层为何未及时响应状态读取。
- 18:55 这次 ANR 前最后一个分段代理样本没有失败分片、正在缓冲或自动重取链。内存占用偏高，但这次退出标记是 ANR，不能认定为低内存杀进程。完整历史中另外包含原生崩溃，见下面的复核补充；用户上滑结束应用、覆盖更新结束旧进程不能计为播放器崩溃。

## 2026-11-17 复核补充

重新核对全部 12 条系统退出记录后，确认历史中有 3 条主进程 ANR（11 月 16 日 00:16:02、00:40:12、18:55:41，北京时间），以及 01:05:59 的一次主进程原生 SIGABRT。只有 18:55 的 ANR 有本次已核对的完整线程栈；不能把另外两次 ANR 也直接归因于同一个函数。

解压后的 `anr-trace-6.txt` 名称容易误导：其内容实际是原生崩溃线程栈，包含 `BLASTBufferQueue::acquireNextBufferLocked`、`Surface::queueBufferImpl`、`vulkan::driver::QueuePresentKHR` 和 `libflutter.so`。它说明图形提交链路发生了崩溃，但没有完整 abort message，尚不能区分系统/驱动兼容性、Flutter 引擎或视频 Surface 生命周期问题。这里的 Vulkan 是 Flutter 合成提交路径，不能据此推断 mpv 使用了 Vulkan 视频解码。

因此，上述异步状态读取修复只针对已定位的同步等待风险，不覆盖这一条独立的图形崩溃。进一步审查及优化优先级见 [播放器性能与稳定性审查](PLAYER-AUDIT-20261117.md)。

## 修复

`NativePlayer.getProperty` 改用 `mpv_get_property_async`，通过请求编号匹配 `MPV_EVENT_GET_PROPERTY_REPLY`，默认最多等待两秒。正常不可用属性仍返回空字符串；超时抛出 `TimeoutException`，应用停止本轮采样并保留原有监测状态，下一轮再试。这样不会把超时误判为不支持画面检测，也不会在一次采样中继续堆积十余个超时请求。

读取结果在下一次 `mpv_wait_event` 前复制成 Dart 字符串，不释放由 mpv 持有的事件内存。超时后移除 Dart 请求；迟到回包直接忽略。关闭播放器前完成剩余读取等待，禁止新请求访问已销毁的句柄。

公共 `setProperty` 复用已有异步属性写入流程，等待每项完成后才执行下一项，保留 Android 表面更新的属性顺序。自定义属性监听直接使用事件携带的字符串，回调等待其他属性时不占住原生事件分发。属性写入的发送失败及同步配置分支也释放请求和名称内存。

本轮保留播放器、硬解模式、视频纹理尺寸、画质、分段缓存和连接策略。真正的解码器或 GPU 永久卡死仍需单独诊断；这次处理的是日志中可定位的主线程同步等待，不能承诺已消除用户所有退出情况。
