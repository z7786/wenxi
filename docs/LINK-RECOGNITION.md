# 网盘链接识别

解析页、剪贴板提示和系统分享共用链接识别规则，支持分享文案、链接和提取码。识别阶段不请求网盘；开始解析后由对应连接器验证分享并读取文件列表。

点击剪贴板提示条或「立即解析」会切换到解析页并直接开始解析；点击解析页的「已识别」提示或多链接列表中的一条链接，也会直接解析该链接。提取码随链接带入，成功后打开文件列表；需要登录或解析密码时沿用原有提示。仅识别、输入或粘贴内容不会自动发起解析。

当前可以识别 16 个网盘来源，其中 14 个支持分享解析。首页“支持类型”按连接器能力生成；微云和蓝奏云优享版的个人盘功能不等于分享解析能力。

## 链接中的“删”字

粘贴、剪贴板提示和系统分享会自动清理 HTTP/HTTPS 链接中用于干扰识别的独立“删”字。例如 `https://删github.com/删diabl0w/删DFRoot/releases` 会还原为 `https://github.com/diabl0w/DFRoot/releases`。标记可以位于协议、域名、路径和查询参数中，支持连续标记、无协议域名以及 `%E5%88%A0` 编码形式。

清理只作用于链接候选片段；与其他汉字相连的“删除说明”等中文名称保持原样。只移除标记，不重新编码 URL，不调整大小写敏感的路径、已有转义或参数顺序。清理后的地址仍按正常协议、域名、账号信息与转义规则校验，并由原有来源规则判断是否可解析。多链接的提取码归属和重复链接合并使用同一份清理后的文本，单链接历史记录保留原始粘贴内容。

## 口令解析

在解析页点击「口令解析」，手动选择夸克、迅雷或 UC，再粘贴口令。不会自动判断口令所属网盘，也不会因解析失败改用其他网盘请求。成功后直接打开分享文件列表，提取码自动保留，下载仍沿用原有流程。

- 夸克：支持「咐置…叩苓」中文口令和「/~…~:/」字母数字口令，可粘贴包含口令的完整分享文案。
- 迅雷：支持中文分享口令。
- UC：支持中文口令和「~U_C…~」字母数字口令。

页面记住上次选择的网盘；不同网盘的输入在当前页面内分别保留。历史记录保存解析后的分享链接，重新打开无需再次查询口令。

本地正式构建通过 `.local/cloud-command.defines.json` 注入 `ASTERLINK_QUARK_COMMAND_KEY` 和 `ASTERLINK_UC_COMMAND_KEY`，共用构建脚本会自动读取。此文件不提交到仓库；未配置时仍可正常解析分享链接。

## 城通链接

支持 `ctfile.com`、`ctfile.cn`、`400gb.com`、`545c.com`、`pipipan.com` 及其子域名，例如 `url69.ctfile.com`。识别 `/f/…`、`/file/…`、`/d/…`、`/dir/…`、`/s/…`，兼容 `#/…` 路由、无协议前缀和末尾斜杠。首页、登录页、帮助文章及跳转参数内的地址不会被当作分享。

城通优先读取 URL 中的 `p`，其次读取 `pwd`、`pass`、`passcode`、`password`、`accessCode`、`code`；支持普通查询参数、`#` 路由参数和独立 `#提取码`，参数名忽略大小写。自动密码接受 1–12 位字母数字，过长时不截断；URL 内密码优先于周围文案。支持紧贴链接的“（访问密码：1664）”、Markdown 链接和多链接分别配码。

## 天翼 H5 复制链接

支持 `https://h5.cloud.189.cn/share.html#/t/分享编号`，以及直接接在链接后面的“（访问码：m6h5）”。括号与访问码标签支持原文、URL 编码和混合编码；只解码并分离这段分享文案，保留地址其余部分的转义和参数顺序。网页版 `/web/share?code=…`、短链 `/t/…`、无协议链接和 Markdown 链接沿用相同规则。

分享编号与访问码分别传入现有天翼解析流程，继续优先匿名读取分享。`code` 始终是分享编号；URL 内有效密码参数优先于附带文案。复制、剪贴板提示和多链接粘贴会保留各自的访问码，手动更正后不会再次读取原文中的旧码。

## 小飞机链接

官方复制格式为 `https://share.feijipan.com/s/分享编号?code=提取码`，文件与文件夹使用同一规则。支持无协议前缀、末尾斜杠、`#/s/…` 路由、Markdown 链接，以及紧贴链接的“（访问密码：a123）”。分享编号保留大小写；首页、登录页和相似域名不作为分享。

提取码优先读取 URL 的 `code`，兼容 `pwd`、`pass`、`passcode`、`password`、`accessCode` 与 `#a123`；仅接受完整的 4 位字母数字，不截断过长值。链接内有效提取码优先于周围文案，多条分享各自配码。

## 提取码顺序

1. 读取 URL 查询参数。参数名忽略大小写，按 `pwd → pass → passcode → password` 的顺序选值，与参数在 URL 中的位置无关。
2. 查询参数没有合格结果时，读取 `#` 路由内 `?` 后的参数，使用相同顺序。
3. 再尝试原始 URL 中上述四类参数的正则匹配。
4. 最后读取周围文案中的「提取码 / 密码 / 访问码 / 口令 / pwd」。同一条分享有多个标签时，最后一个合格标签生效；URL 内合格码始终优先。

自动提取码处理会先解码、去空白，再截取上限：普通网盘最多 4 位且结果必须为 4 位，蓝奏最多 12 位。文案正则最多读取 12 位字母数字，普通网盘只接受恰好 4 位的匹配，蓝奏接受 1–12 位。`http/https` 不作为提取码。手动填写仍优先，允许填写实际需要的码，不受自动识别长度限制，也不改 URL。

保留此前可用的 `#abcd`、`#pwd=abcd`、`accessCode`、非天翼 `code`、中文「为/是」和括号格式作为兼容补充。多链接各自按临近文案配码、重复 URL 合并、签名 URL 的路径转义与查询顺序继续保留。剪贴板只保留分享或已支持的下载类型，不保留无关文案；解析页首次选择优先落在网盘分享上，其他链接仍可手动选择。
