# 跨盘传输

在文件菜单选择跨盘传输后，任务进入「传输 → 上传」。目标支持秒传且来源有可信 MD5 时先请求秒传，未命中则下载原文件后上传；目前 MD5 目标为 123、天翼和光鸭。秒传是否命中由网盘接口决定。

跨盘任务默认同时运行 3 个，在「我的 → 下载设置 → 同时跨盘任务数」或上传页面的设置按钮可调整为 1–8 个；这是独立于同时下载任务数的设置。其余任务按加入顺序排队，每个任务内仍逐个处理文件。提高上限立即补充任务，降低上限保留已开始的任务，结束后按新上限调度。各任务使用独立取消范围，继续和删除记录会等待本任务的旧执行结束。相同账号、空间、目录内的同名文件和文件夹共用写入锁，处理前重新读取目标，中转下载共同预留剩余缓存空间。

中转下载与上传分别显示进度。中转下载复用普通下载的 Gopeed 内核，沿用来源网盘及下载路线的连接数、限速、重试和网盘连接限制；小文件或不支持 Range 的来源由内核减少连接或单连接下载。每个文件开始下载时读取配置，已建立的断点保留原配置。下载中断后保留分片，继续时核对来源和远端文件身份；身份变化或无法可靠续传时重新下载。

下载完成后校验文件，同时计算 MD5 和 SHA-1，上传复用这些结果。上传失败时保留完整的中转文件；继续任务会先核对来源、目标和缓存校验值，目标已确认保存则跳过，否则重新上传。缓存损坏或丢失会重新下载。校验失败的文件会清理。下载目录仍为应用中转缓存，单个文件下载完成后再上传，多个跨盘任务可同时推进。

删除任务记录会清理该任务的中转文件。「清理失败跨盘传输」批量删除已停止且仍可重试的任务和缓存，保留正在传输的任务及目标网盘中的文件。

实现对比参考 OpenList `25da9901f50fecc6cb417193680f0f3cfe2ffcdd` 和 AList `92e745360766cce32564f94a468cb576f577d27e` 的跨存储复制及驱动上传逻辑。两者跨存储也通过源文件流和目标驱动上传；123 使用 MD5，夸克/UC 使用 MD5 与 SHA-1，115 还要求 SHA-1 和片段校验。应用不会把普通 ETag 或不匹配的摘要当成通用秒传凭证。
