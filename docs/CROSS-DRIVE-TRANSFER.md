# 跨盘传输

在文件菜单选择跨盘传输后，任务进入「传输 → 上传」。目标支持秒传且来源有可信 MD5 时先请求秒传，未命中则下载原文件后上传；目前 MD5 目标为 123、天翼和光鸭。秒传是否命中由网盘接口决定。

跨盘传输默认同时处理 3 个文件，上传页面直接显示「同时处理数」下拉选择，提供 1、2、3、5、8 和自定义输入，允许 1–8 个；也可在「我的 → 下载设置 → 同时跨盘任务数」修改。这是独立于普通下载任务数的设置。一次选择多个文件或整个文件夹时，扫描后的文件也进入并发队列，不再等上一文件上传结束才下载下一文件。多个跨盘批次共用文件并发上限，批次之间轮流获取空闲名额，批次内按文件顺序排队；同时扫描的批次也不超过此上限。提高上限立即补充文件，降低上限保留已开始的文件，结束后按新上限调度。各批次使用独立取消范围，继续和删除记录会等待该批次全部文件的旧执行结束；账号失效、授权取消和限流会停止该批次的其他文件，普通文件错误不阻止后续文件。相同账号、空间、目录内的同名文件和文件夹共用写入锁，处理前重新读取目标，中转下载共同预留剩余缓存空间；同一批次的目录读取与创建复用正在执行的请求，移动数据确认只提示一次。

中转下载与上传分别显示进度，批次速度汇总各个正在传输的文件。中转下载复用普通下载的 Gopeed 内核，沿用来源网盘及下载路线的连接数、限速、重试和网盘连接限制；小文件或不支持 Range 的来源由内核减少连接或单连接下载。内核保留足够的运行名额，由普通下载与跨盘管理器分别限制并发，不再被固定 3 个内核任务的上限拦住。每个文件开始下载时读取配置，已建立的断点保留原配置。下载中断后保留分片，继续时核对来源和远端文件身份；身份变化或无法可靠续传时重新下载。

下载完成后校验文件，同时计算 MD5 和 SHA-1，上传复用这些结果。上传失败时保留完整的中转文件；继续任务会先核对来源、目标和缓存校验值，目标已确认保存则跳过，否则重新上传。缓存损坏或丢失会重新下载。校验失败的文件会清理。下载目录仍为应用中转缓存，单个文件下载完成后再上传，多个跨盘任务可同时推进。

删除任务记录会清理该任务的中转文件。「清理失败跨盘传输」批量删除已停止且仍可重试的任务和缓存，保留正在传输的任务及目标网盘中的文件。

实现对比参考 OpenList `25da9901f50fecc6cb417193680f0f3cfe2ffcdd` 和 AList `92e745360766cce32564f94a468cb576f577d27e` 的跨存储复制及驱动上传逻辑。两者跨存储也通过源文件流和目标驱动上传；123 使用 MD5，夸克/UC 使用 MD5 与 SHA-1，115 还要求 SHA-1 和片段校验。应用不会把普通 ETag 或不匹配的摘要当成通用秒传凭证。
