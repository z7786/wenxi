# 解析通道与远程规则

当前客户端已支持 **v4 本地流程规则**：后台下发接口流程、轮询、分页和可组合签名函数，由 App 直接请求原站。先升级一次客户端后，能力范围内的站点变化只需后台修改并发布规则。语法、预算、维护步骤和实测结果见 [v4 远程流程规则](WORKFLOWS-V4.md)。

百度、夸克、UC、迅雷、123 和移动云盘分享支持从后台获取公益解析规则与已验证的共享密码。通道可以由 App 直接请求解析站，也可以交给后台完成会话验证、排队和取链。文件内容由 App 从最终下载地址传输；原有网盘账号及常规解析流程保留。

除百度外，默认继续使用常规解析，用户可在解析页或分享文件页切换公益通道。通道选择按网盘分别记忆，只显示适用于当前网盘、已发布且启用的规则。个人网盘文件管理仍使用原账号接口。

此前多网盘通道使用引擎 v3，需要先安装一次包含多网盘接入的 App；当前 v4 客户端继续兼容这些规则。PanApiDown 按百度、夸克、UC、迅雷、123、移动拆成独立通道，密码分别验证和保存，共用本机固定的站点设备标识。列表允许无密码时可以先浏览，下载前再读取密码；原站提前要求密码或后台关闭自动填入时，会显示密码窗口。

夸克与 UC 下载会带上原站返回的下载 Cookie 和 Referer。凭据限定在规则声明的下载域名中使用，App 自己的网盘登录 Cookie 不会发给解析站。夸克按下载节点合并对应凭据；分享令牌和文件取链参数失效或任务恢复时，会重新读取目录核对文件。

## 按网盘开放公益解析

后台「解析规则 → 网盘公益解析」可分别开放或关闭百度、夸克、UC、迅雷、123 和移动云盘，修改后自动保存。默认全部开放；总开关优先于各站点开关，实际可用通道仍需单独启用并发布。

- 关闭某个网盘后，后台停止下发该网盘的公益通道，并拒绝客户端读取共享密码、提交密码及发起新的后台解析或取链。管理员仍可维护站点与测试草稿。
- App 收到新配置后隐藏对应公益入口，旧分享和恢复任务也不能继续发起公益解析或取链。常规解析、账号下载和个人网盘管理保留，已取得直链的文件传输不主动中断。
- 重新开放后恢复已发布且单站启用的通道，原密码、站点配置及用户的通道偏好保留。不会自动启用停用站点或发布草稿。

开关保存在签名清单的 `publicParsing` 字段，按网盘名称填写布尔值；旧配置缺少此字段时默认开放。启动及运行中每 15 分钟检查配置，断网时使用上次已验证的设置。开关变化后应重新导出并上传备用 JSON，防止备用文件继续保留旧设置。旧安装包需要先升级一次，才能获得本次入口隐藏和旧任务检查能力。

## 用户流程

1. 在对应网盘分享解析区域选择公益通道。只列出后台已发布且启用的通道，并记住该网盘的上次选择。
2. 普通通道允许自动填入时复用共享密码；缺少或已失效时显示「解析密码」窗口。后台关闭自动填入后，每次新解析都先显示窗口，由用户填写验证。
3. 根据该通道的领取说明获取完整密码，填写后提交验证。支持中文、字母、符号和有意义的空格，不限定为三个字。
4. 后台验证通过后保存共享密码，点击「继续解析」进入分享页面；允许自动填入的通道可供其他用户复用。取消输入会保留原分享链接，也可以切换为账号下载。

2026-10-20，`dg22_public`（公益通道一）与 `dg22_uc`（临时通道）已发布 `engine: 1` 直连规则，发布序号分别递增为 4、5。两个通道均设置 `passwordPrompt.autoFill: true`、`buttonEnabled: false`，并移除 `webFlow`；由本机密码更新器获取最终密码、提交后台验证后共享，用户无需手动取密或登录 UC。随后按用户要求停用通道一 `dg22_public`，历史编号 `mf_dg22` 继续停用；临时通道改为 `minClientRevision: 1`，向新旧客户端全部开放。此次仅更新后台，已接入后台的旧安装包刷新规则后即可使用临时通道。

升级规则引擎之前的安卓 1.8，刷新后可以看到临时通道、六、二。通道五和小白依赖 v4 的签名、动态请求或稳定设备计算，暂不向旧版下发，也未改为后台转发。历史 v2 客户端曾通过空缓存共享密码读取和取链验证；站点后续改变请求检查后，实际可用性仍受客户端请求行为与设备网络影响，不能仅以清单可见判断可用。

2026-10-21，临时通道发布第 7 版规则，列表、刷新列表和取链三个步骤均明确指定 `Content-Type: application/json`。客户端 v1 与 v4 引擎已修复强制覆盖此头的问题，按不区分大小写的头名称保留规则声明的完整值；未声明时沿用 JSON 的 `application/json;charset=utf-8` 与表单的 `application/x-www-form-urlencoded` 默认值。已有安装包仍会覆盖，需安装包含此修复的客户端才能按新规则发出精确类型。代理下实际 App 引擎列文件及取链均通过，本机直连仍收到原站 403；后台使用的代理不会替手机代理，也不代表手机直连已恢复。

这两个 v1 规则在下载前重新读取目录，用最新的 `randsk`、`uk`、`shareid` 和用户所选 `fs_id` 请求下载地址；可选 `dlink` 发送空列表，由原站按文件编号取链。结果仍严格核对所选文件编号，拒绝不一致或多编号响应。此写法无需 v4 的 `filter` 或值步骤，当前原站已实测支持；若以后强制要求新 `dlink`，需重新评估规则能力。API 使用已验证的请求头和 `checkrand` 算法，`deviceGroup` 保持 `mf_dg22`。列表、取链和文件下载继续由用户设备直连。原站换密期间后台尚未取得有效密码时，提示稍后重试；旧客户端已有的输入框仍可能显示，配置不增加强制人工步骤。

本机更新器按网页更新时间加 30 分钟和缓冲更新最终密码，UC 第一层访问密码最多缓存至次日零点。电脑和更新器需保持运行；更新器及操作说明仅在本地维护，不随客户端仓库发布。正式下发已通过现有客户端与历史 v2 客户端空缓存解析、取链验证，历史 v2/v3 引擎的多文件及大整数文件编号检查通过；仅取下载链接，未下载完整文件。

手动验证仅对本次分享生成许可，文件浏览、下载及重启后恢复任务可以复用；新解析仍按站点设置判断。许可到北京时间次日零点失效，明确密码错误也会撤销。密码保存在本地应用私有存储中，任务信息只携带随机许可编号。

文件列表、下载过程中遇到明确密码错误才上报。额度不足、网络故障、分享失效不会当成密码错误。若原站需要人工审核，窗口提供审核结果查询和重新获取入口。

密码缺失和密码错误共用一套后台配置。在「站点管理 → 编辑站点 → App 密码弹窗」可修改标题、正文、获取密码按钮文字和跳转地址，也可隐藏按钮或关闭「自动填入可用密码」。正文可选普通文本或丰富排版，支持标题、加粗、列表、引用、表格、分隔线以及 HTTPS 链接和图片，编辑时可实时预览。App 中可长按选择文字或点「复制内容」复制全文；按钮用浏览器打开获取页面。修改这些设置不会清除已共享密码，也不需要重新发布解析规则。

弹窗配置随签名清单下发。`passwordPrompt.format` 默认为 `text`，丰富排版为 `markdown`；`passwordPrompt.autoFill` 默认为 `true`。打开密码窗口或点击「重新获取」时，会异步检查最新配置；拉取失败时保留已验证的文案。需要先安装一次支持这些字段的 App，后续文案、按钮和自动填入设置无需重新编译。旧清单使用默认提示与自动填入策略，旧安装包不会自动获得新的弹窗和账号判断行为。

无需密码的后台通道会跳过密码窗口，显示排队、解析和取链进度。解析成功后直接进入分享文件页面；遇到需要人工验证的情况，可以选择「网页解析」或其他通道。

后台通道只接收所支持的网盘分享链接及其提取码，不接收 App 的网盘账号 Cookie、登录密码或 Token。刷新文件列表和点击下载复用本次解析结果，不重复提交转换；结果保存 30 分钟，过期后提示重新解析。取消解析时会通知后台停止该任务，后台另有超时回收。

## 网页获取解析密码

需要密码的直连通道可以配置 `passwordPrompt.webFlow`。后台入口为「站点管理 → 编辑站点 → App 密码弹窗 → 在 App 网页中自动获取密码」，支持网页地址、允许域名、访问密码来源、固定访问密码、自动共享、浏览器标识、填写及读取脚本、检查间隔、超时和本次分享有效期。`dg22_uc`（临时通道）此前通过此流程读取 `mmhq.dg22.top` 的 UC 口令和最终密码；2026-10-20 已与通道一一起改为后台共享密码，关闭 App 网页取密。以下为其他需要网页取密通道仍可使用的通用能力。

用户点击「网页获取并继续」，在自己的设备上完成网页的人机验证。`firstPasswordSource: "ucCommand"` 时，脚本请求现有 UC 口令解析和下载能力，把伪装压缩包按文本读取，提取第一行的全部中文字符作为访问密码；只读取前 4096 字节，不使用旧来源或每日解析密码缓存。已登录时使用当前 UC 账号，否则使用游客下载，转存文件由原清理队列回收。App 自动填写访问密码、读取网页最终密码并继续解析。返回、跳转、重载、超时和读取期间账号变化会使旧结果失效。

`sharePassword: true` 时，网页取得最终密码后自动异步提交，后台沿用原校验器验证通过才共享；手动填写的密码在实际解析成功后提交。访问密码、UC 口令、账号凭据和设备信息不会提交。共享失败不阻塞本机解析，重复请求合并并短暂退避。`autoFill: true` 时新分享可复用已验证的共享密码，缺失或服务不可达时仍可网页取密。省略新字段默认固定访问密码、本机模式，原外部浏览器入口继续保留。

本地许可保存在应用私有目录中，绑定站点和取密配置指纹，仅供当前分享的浏览、下载及重启恢复使用。有效期取 `cacheSeconds` 和北京时间次日零点中较早的时间；取密配置变化或原站明确拒绝密码时失效。日志不记录密码、脚本内容或验证码令牌。

UC 口令调用和自动共享首次需要升级 App，之后能力范围内的网页变化可以后台下发。取密配置随原有 RSA 签名清单验证，规则引擎编号保持 4；原网页取密版本可手动填写访问密码，更早的 App 忽略网页配置并保留原来的通道集和获取入口。保存配置不会改动解析规则正文；静态备用 JSON 仍需按原流程重新导出上传。

脚本是同步 JavaScript 函数体，通过 `config.firstPassword` 读取访问密码。在 `config.ucCommandSupported` 为 true 时可返回 `{status:'ucPassword',command:'网页当前口令'}`；读取完成后核对 `config.ucCommand` 与页面当前口令一致再填写密码。其余状态为 `{status:'waiting',message:'提示'}`、`{status:'success',password:'最终密码'}`、`{status:'error',message:'原因'}`。脚本最多 24000 个 UTF-8 字节，检查间隔 500–5000 毫秒，超时 30–600 秒，有效期 60–86400 秒。主页面仅允许配置中精确列出的 HTTPS 域名；验证码仍由用户完成。

相关实现为 `lib/data/parser_rules/password_web_flow.dart` 与 `lib/ui/parser_password_web_page.dart`；后台完整字段说明和脚本示例见后台项目 `docs/PASSWORD-WEB-FLOW.md`。

## 新旧客户端分发与共享密码

App 继续使用规则引擎 v4，另以 `X-Parser-Client-Revision: 2` 声明支持 UC 网页自动取密和自动共享。没有该请求头的已发布安装包视为客户端能力 1。后台站点设置 `minClientRevision: 2` 后，仅向支持该能力的客户端返回新通道；原站点默认值为 1，原规则和设备标识不变。站点列表和签名规则清单使用同一过滤条件。

各客户端能力独立保存签名清单，并在升级时保持递增版本。备用 JSON 原有根节点和 `engines` 保留旧版视图，`clients["2"]` 提供新版视图。旧安装包忽略新增字段，新安装包优先选择对应的签名副本；导出后仍需更新远端静态文件。

后台 `passwordGroup` 将不同通道的密码共享起来；留空表示独立保存。组内必须使用相同原站地址、校验器和校验配置。验证通过后分别加密保存到各通道并递增各自的密码版本，旧 App 仍通过原站点编号读取。错误候选、网络故障或未审核的密码不传播；已确认失效的同一密码会同步失效，过时的错误反馈不会清除较新的密码。通道的启停和可见性不随密码同步改变。

`dg22_uc`、`dg22_public` 与旧编号 `mf_dg22` 使用 `dg22_shared` 组。只共享最终解析密码，UC 口令及网页第一层访问密码不进入共享服务。通道一的新旧编号均已停用；临时通道使用 v1 规则、最低客户端能力 1，新旧客户端都能显示并读取共享密码。自动更新器向仍启用的 `dg22_uc` 提交，不受通道一停用影响。

## 后台地址由更新配置下发

在 App 原有的更新配置 JSON 中增加以下字段，公告、网盘开关和更新信息保持原样：

需要先安装包含此能力的新版 App，之后迁移后台只需修改这份 JSON 中的地址。

```json
"parserHub": {
  "url": "https://your-parser-hub.example"
}
```

填写手机和电脑能访问的后台根地址，可使用 HTTP/HTTPS、端口和部署子目录，不带 `/admin/`、查询参数或片段。App 启动先读取上次缓存的地址，拉取更新配置后立即应用新地址，运行中每 15 分钟检查一次。变更地址不需要增加 `revision` 或修改公告 ID。

更新配置暂时访问失败、字段缺失或地址无效时，保留上次有效地址；首次安装没有缓存时，可使用构建配置中的可选备用地址。这里仅公开地址，接口密钥及规则签名公钥继续随 App 构建配置提供，不放进公开的更新 JSON。

地址切换会丢弃旧地址尚未完成的规则、密码响应，正在直连文件的下载继续进行。同一签名身份保留原规则存档、通道选择和设备标识，也兼容旧版按地址保存的缓存。迁移后台时需同时迁移数据库并沿用原接口密钥和签名密钥；更换密钥本身仍需更新 App 的接入配置。

## 构建配置

后台「接口接入」可以导出以下配置，保存为项目的 `.local/parser-hub.defines.json`。字段示例见 [parser-hub.example.json](../config/parser-hub.example.json)。

| 构建参数 | 内容 |
| --- | --- |
| `ASTERLINK_PARSER_HUB_URL` | 可选的首次安装备用地址；优先采用更新 JSON 的 `parserHub.url`，可以留空 |
| `ASTERLINK_PARSER_HUB_KEY` | App 接口 Bearer 密钥 |
| `ASTERLINK_PARSER_HUB_PUBLIC_KEY` | 服务器签名公钥 PEM 的 Base64 编码 |
| `ASTERLINK_PARSER_RULES_BACKUP_URL` | 可选的 HTTPS 备用 JSON 地址，留空关闭 |

`tool/build-android.ps1`、`tool/build-windows.ps1` 等使用公共构建工具的脚本会自动附加该文件。直接使用 Flutter CLI 时，需要显式加上 `--dart-define-from-file=.local/parser-hub.defines.json`，并保留正式版所需的其他构建参数。

`.local` 已被 Git 忽略。不要把真实接口密钥填进公开示例；服务端签名私钥不进入 App。未配置该服务时无法接收新增规则或共享密码；当前临时通道 `dg22_uc` 的 v1 规则适用于已经连接当前后台的各代规则引擎客户端。

## 更新与恢复

- App 启动和运行中每 15 分钟检查一次清单；疑似规则结构错误时最多额外检查一次，短时间内不连续重试。
- 规则使用 RSA-SHA256 签名，App 用构建时固定的公钥校验，并拒绝旧版本覆盖新版本。该版本机制只用于解析规则。
- 主配置发生网络故障、格式异常或签名失败时，尝试备用 JSON；备用也不可用时沿用已验证缓存。主配置正常返回时不请求备用地址，下次刷新仍优先访问主配置。首次安装尚无缓存且暂未取得规则时，默认通道可使用原内置解析；成功取得的空清单则表示没有可用远程通道。
- 分享页面及任务只保存规则包摘要引用，规则包单独存档，避免大量下载任务重复保存整份规则。旧任务使用原规则，但仍受最新已获取的网盘公益总开关控制；需要新版规则时会提示重新解析分享。
- 共享密码按后台签名身份与站点隔离保存；同一后台换地址后可以继续读取原缓存。明确拒绝的密码版本会留下本地摘要标记，服务端仍返回相同旧值时也不会反复使用。较新的有效密码可以正常更新。
- 多个任务可以复用一次共享密码请求，取消其中一个任务不会取消其他任务的读取；应用关闭时会取消未完成请求。

这套机制需要用户先安装一次包含对应规则引擎的版本。当前 App 请求携带 `X-Parser-Engine: 4`，兼容适用的 v1–v3 规则；未提供此头的旧 App 继续获得 v1 清单。后台同时按最低 `engine` 和可选最高 `maxClientEngine` 筛选规则，上限含边界，省略时没有上限；旧 App 会忽略这个额外字段。新版清单的 `revision` 会高于已签发的低引擎清单，静态导出也按引擎递增生成，已验证从旧清单缓存升级不会误报 `RULE_ROLLBACK`。

## 导出备用 JSON

后台「解析规则 → 导出 JSON」生成 `parser-rules.json`，包含当前开放、启用且已发布的规则、领取说明、密码弹窗配置及各网盘公益总开关。将文件原样上传到 Gitee 的公告目录，规则、弹窗或总开关修改后重新导出覆盖。本项目的备用地址配置为 `https://gitee.com/dzys/cs/raw/master/parser-rules.json`，不会自动上传文件。Gitee 的 `blob` 文件页面地址也会转换为 `raw` 直读地址。

导出保留原始规则包及签名，附加一份绑定原规则包摘要的签名凭证，有效期 365 天。根节点保留 v2 内容，`engines["3"]`、`engines["4"]` 分别提供独立签名内容。新 App 优先读取 v4；旧备份没有 v4 时可读取 v3，旧 App 继续读取对应内容。App 校验固定公钥、有效期与规则版本，不接受旧备份覆盖新版，也不会因主备切换改变正在下载的任务。普通 API 清单仍维持 7 天有效期。请求备用文件不发送接口密钥、账号 Cookie 或设备标识；文件没有共享密码、管理密码或私钥。

备用 JSON 只备用配置读取。共享密码服务、密码提交和服务端执行的解析通道仍需要原后台在线；静态文件无法替代服务端程序。启用这个备用入口需要先安装包含本次修改的 App。

对于直接请求解析站的 v1 规则，修改 URL、请求字段、响应映射、错误码、分页以及已支持的签名步骤，通常可直接后台发布；新算法仍可能需要升级 App。对于 v2 后台通道，签名、会话和上游结果格式的变动主要修改 PHP 适配器，App 继续使用统一任务协议。新增用户交互或超出任务协议的能力仍需更新 App，远程规则也不能修复原站自身停服或额度限制。

2026-10-17，`mdx_convert` 和 `mdx_quark` 已通过后台测试及 App 真实 Range 下载，发布并启用了 v4 直连规则。它们仅对 v4 客户端可见。此前原站无权限导致的停用记录已被此次复测更新。

2026-10-14 多网盘实测中，PanApiDown 百度已通过取链和 App 实际 Range 读取；UC、迅雷可列文件，但当前样本被原站小文件解锁要求拦截。123 返回上游请求失败，移动返回账号池不足，夸克需要独立有效密码；NetDiskX 夸克返回 IP 无业务权限。这些未完成真实下载验证的新增通道保留停用草稿，原站恢复后可在后台重测发布。站点解锁、额度和账号池限制不会被当成共享密码错误，也不会自动绕过。
