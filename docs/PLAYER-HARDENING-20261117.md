# 播放器第一批稳定性优化（2026-11-17）

本次落实 `PLAYER-AUDIT-20261117.md` 的第一批建议，基于当前工作区，未编译安装包或发布。先前针对同步属性读取的 ANR 修复保留。本次没有更换播放器、降低画质或缩小网络缓存。

## 实现

### 原生销毁移出界面线程

`NativePlayer.dispose()` 先等待正在创建的视频输出、原生 stop 确认，再释放输出与事件消费者。原有五秒 Surface 宽限期保留；之后只把动态库路径和句柄地址传入工作 isolate，由其执行可能阻塞的 `mpv_terminate_destroy`。销毁完成后才关闭原生回调 trampoline，避免旧线程调用已释放回调。

新增 `nativeDisposed` 完成信号；后端记录 `player.native_disposed` / `player.native_dispose_failed`。普通 `dispose()` 完成表示输出、事件已脱离，仍不等同于所有原生资源已释放。

关闭调用最多等待十秒。超过期限会报超时，底层清理继续等待 stop 的真实回复；不会因超时释放仍被解码器使用的 Surface，也不会强杀工作 isolate。重复关闭共用同一清理流程。iOS 使用的事件 isolate 改成明确的停止确认，并等当前 Dart 事件回调返回，移除原先两秒后强杀事件 isolate 的做法。

这是在安全收尾与响应性间的取舍：如果原生核心永久不返回，相关资源仍可能保留；不能安全强行回收活跃指针。应用已有的退休失败逻辑会保留来源租约与临时文件。这批不宣称消除所有资源滞留，也没有缩短正常 Surface 宽限期。

### 原生命令有期限并清理异常分支

普通异步属性写入和 command 默认五秒等待；get 保留两秒。所有分支通过 finally 清理参数、数组和请求表，迟到回包忽略。命令数组按实际长度加一个空指针分配，替代固定 128 项；命令错误日志只记录命令名称，避免附带链接或请求头。

关键属性 `vo/wid/hwdec/vid/pause/speed/volume` 被拒绝时向调用方报告失败；非关键可选属性仍兼容旧内核的“不支持”结果。超时也会向调用方报告，后续控制门不再永久悬挂。初始化失败传递给等待方；播放器 idle 与视频初始化等待有十秒期限。底层创建阶段的原生同步调用不在这批重写范围内。

另按 mpv 0.36 C API 修正 `MPV_FORMAT_FLAG` 参数：使用 C int（0/1），避免原先一字节 Bool 分配与 C 接口要求的大小不一致。

销毁专用 stop 是例外：调用者有十秒期限，但内部保留等待真实回复，不能用普通命令期限推断已经停止。

### 初次打开与播放中恢复统一软解保护

自动软解要求已知尺寸且像素数不超过 1920×1080、已知有效帧率、当前倍率不超过 1 倍、帧率乘倍率不超过 30。优先使用选中视频轨的原始帧率，避免用掉帧后的采样数低估负载。

4K、高帧率、未知元数据以及高倍速播放不再在首次失败后静默转软件解码。初始化命令超时、字幕设置阶段、系统展示阶段失败也不会直接触发软件重建。手动关闭硬解仍可使用，正常硬解播放路径不变。

这会有意减少“未知格式自动软解尝试”：有些可用软解播放的文件可能需用户手动选择。1080p/30 的上限只是保守策略，不保证低性能设备流畅。

### BT 与边下边播转发监测开关

`DelegatingPlaybackBackend` 补齐 `setVideoMonitoringEnabled` 转发，后台/前台状态能够到达真实后端，避免画面监测在不适用的状态触发误判。这里不声称所有周期统计采样都已停止。

上述套件存在重复项，数字不可相加为独立用例数。原生测试主动挂住真实 on_load 回调验证超时与迟到回复；创建额外 mpv 客户端让 terminate_destroy 等待，确认界面 isolate 的计时器仍推进；另直接测试事件 isolate 等待在途回调后才确认停止。

Windows 上模拟 Android 输出方法调用只验证 Dart 调用顺序，不是 Android GPU/Surface 真机测试。此前日志中的独立 Vulkan/Surface SIGABRT 尚未定位，这批不能保证解决。仍需反馈机型进行两小时播放、横竖屏、切集、后台恢复和退出复测。低内存缓存、小窗尺寸及图形兼容对照属于后续批次。
