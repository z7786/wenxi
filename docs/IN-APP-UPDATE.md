# App 内更新

更新弹窗提供「App 内更新」和「浏览器更新」。App 内更新复用下载管理，支持暂停、继续和重试；关闭弹窗不会取消下载，同一版本、地址、提取码和完整性信息对应的任务会被复用。安装包摘要或大小改变时使用新的任务，避免复用被替换的安装包。

下载失败后，「重试下载」沿用原任务继续；「重新下载」会重新解析更新地址并建立新任务，适合安装包被替换或原任务持续失败的情况。

在远程配置 `updates.android` / `updates.windows` 中分别填写对应平台的安装包：

```json
{
  "enabled": true,
  "force": false,
  "version": "1.2.0",
  "build": 120,
  "downloadUrl": "https://example.com/downloads",
  "inAppDownloadUrl": "https://example.com/app-1.2.0.apk",
  "inAppPasscode": "",
  "packageSha256": "",
  "packageSize": 0,
  "notes": "更新说明"
}
```

- `downloadUrl`：浏览器打开的下载页面或安装包地址，沿用原字段。
- `inAppDownloadUrl`：可选，填写已支持网盘的单文件分享链接或安装包 HTTPS 直链。留空时尝试解析 `downloadUrl`。
- `inAppPasscode`：可选提取码。填写后优先使用它，否则使用链接里携带的提取码。
- `packageSha256`：安装包整个文件的 64 位 SHA-256，大小写均可。Windows 的 App 内下载和安装必须提供；缺少时提示使用浏览器更新。Android 可选，填写后在原有 APK 校验之前增加整包校验。摘要对应 `inAppDownloadUrl` 实际下载的 EXE / ZIP / APK，而非浏览器页面或解压后的程序。
- `packageSize`：安装包字节数，0 表示未提供；填写正整数后与网盘文件信息、下载任务和安装前文件长度核对。示例留空的摘要及 0 大小须在发布时替换为本次产物信息。

现有 GitHub 发布工作流输出 `SHA256SUMS.txt`。GitHub 备用更新优先读取选中资产的 `digest=sha256:...` 和 `size`；旧资产无摘要时，仅读取同一 release 的 `SHA256SUMS.txt`，按完整文件名精确匹配。清单冲突或读取失败使本次检查失败，不缓存未完成校验信息的结果；没有对应摘要的 Windows 更新保留浏览器入口。

解析结果必须只有一个文件，不递归查找文件夹，也不从多个文件中猜选安装包。安卓只接受 APK；Windows 接受 EXE 安装器或 ZIP 完整便携包。不能将 Windows 运行目录中的单个程序 EXE 当成安装器发布。

需要账号的网盘会使用软件中已有账号，未登录或链接失效时显示原因，用户仍可点击浏览器更新。如果 `downloadUrl` 指向安装包合集或文件夹，需为两个平台分别填写 `inAppDownloadUrl`，指向 APK 和 Windows 安装包的单文件分享或直链。GitHub 备用更新选中的安装包直链也支持 App 内下载。

夸克更新链接沿用现有免转存下载的自适应选择；Android 手机需要账号转存时，读取系统真实型号、版本、屏幕尺寸、语言和网络，优先使用移动接口，通过已有网页 Cookie 获取移动凭据并生成签名，设备信息不可用或移动流程明确失败后自动回退原网页转存。电脑端默认网页转存，包括恢复带移动偏好的旧任务；平板、电视及尚未验证移动协议的 iOS 同样继续网页转存。该偏好随更新下载任务保存，暂停后继续、重新获取地址和重新下载仍使用当前设备对应的策略。已提交但结果暂未确认时查询同一任务，避免重复转存。语言、网络、协议版本及可省略的设备标识字段见 [夸克移动转存参数](QUARK-MOBILE-TRANSFER.md)。

下载任务保存发布摘要和大小，刷新网盘地址时保留发布的 SHA-256，网盘自身的 MD5 不能覆盖它。沿用下载管理的整包校验，失败时不发布完成文件；暂停、恢复和重新下载保留这些信息。

安卓默认下载目录与用户选择的目录可能返回 `content://` 地址，不能交给 Dart `File` 直接读取。安装前先由现有原生桥读取该地址并生成安装副本、检查 APK 身份，再对实际交给系统安装器的副本校验发布大小和 SHA-256。文件权限丢失、读取失败或摘要不符时停止安装，并保留原下载记录供重试。

已发布的 2.4.5 及此前采用旧校验顺序的安卓客户端，在更新配置提供 `packageSha256` 时可能在读取文档 URI 的阶段失败。面向这些客户端的兼容配置需暂时留空安卓 `packageSha256`，继续保留 `packageSize` 和原生包名、版本、签名校验；待更新链路不再覆盖这些旧客户端后再启用该字段。Windows 必须继续提供 SHA-256。

安卓安装前检查 APK 包名、版本、构建号、签名和最低系统要求，并由系统安装器完成覆盖安装。首次安装需要系统的「允许安装未知应用」权限。下载在前台更新弹窗内完成时会打开安装器；后台完成或关闭过弹窗时，重新打开更新弹窗点击「立即安装」。Windows 下载完成后点击「立即安装」，安装前在独立线程流式重新计算整个文件的 SHA-256，并核对可用大小；成功后继续检查 EXE 的 MZ / PE 或 ZIP 文件头，ZIP 包打开所在文件夹。完整性不匹配时停止打开并提示重新下载。该过程验证文件与 HTTPS 发布信息一致，尚未增加 Windows Authenticode 发布者签名、程序版本或产品身份校验。

安装校验期间关闭更新弹窗，会保留安装包，等待用户重新打开弹窗后点击安装。校验过程中更新撤回、任务取消或删除、保存路径变化、应用进入后台或服务关闭，均不会在校验结束后继续打开安装器。每次安装重新扫描文件，下载后修改文件不能凭旧校验结果启动。

下载完成或打开安装器都不会解除强制更新限制。此功能需要安装包含新功能的 App；旧版本仍按原有浏览器方式更新。
