# App 内更新

更新弹窗提供「App 内更新」和「浏览器更新」。App 内更新复用下载管理，支持暂停、继续和重试；关闭弹窗不会取消下载，同一版本、地址和提取码对应的任务会被复用。

下载失败后，「重试下载」沿用原任务继续；「重新下载」会重新解析更新地址并建立新任务，适合安装包被替换或原任务持续失败的情况。

在远程配置 `updates.android` / `updates.windows` 中分别填写对应平台的安装包：

```json
{
  "enabled": true,
  "force": false,
  "version": "1.2.0",
  "build": 120,
  "downloadUrl": "https://example.com/downloads",
  "inAppDownloadUrl": "https://example.com/app-1.2.0.apk",
  "inAppPasscode": "",
  "notes": "更新说明"
}
```

- `downloadUrl`：浏览器打开的下载页面或安装包地址，沿用原字段。
- `inAppDownloadUrl`：可选，填写已支持网盘的单文件分享链接或安装包 HTTPS 直链。留空时尝试解析 `downloadUrl`。
- `inAppPasscode`：可选提取码。填写后优先使用它，否则使用链接里携带的提取码。

解析结果必须只有一个文件，不递归查找文件夹，也不从多个文件中猜选安装包。安卓只接受 APK；Windows 接受 EXE 安装器或 ZIP 完整便携包。不能将 Windows 运行目录中的单个程序 EXE 当成安装器发布。

需要账号的网盘会使用软件中已有账号，未登录或链接失效时显示原因，用户仍可点击浏览器更新。如果 `downloadUrl` 指向安装包合集或文件夹，需为两个平台分别填写 `inAppDownloadUrl`，指向 APK 和 Windows 安装包的单文件分享或直链。GitHub 备用更新选中的安装包直链也支持 App 内下载。

夸克更新链接沿用现有免转存下载的自适应选择；Android 手机需要账号转存时，读取系统真实型号、版本、屏幕尺寸、语言和网络，优先使用移动接口，通过已有网页 Cookie 获取移动凭据并生成签名，设备信息不可用或移动流程明确失败后自动回退原网页转存。电脑端默认网页转存，包括恢复带移动偏好的旧任务；平板、电视及尚未验证移动协议的 iOS 同样继续网页转存。该偏好随更新下载任务保存，暂停后继续、重新获取地址和重新下载仍使用当前设备对应的策略。已提交但结果暂未确认时查询同一任务，避免重复转存。语言、网络、协议版本及可省略的设备标识字段见 [夸克移动转存参数](QUARK-MOBILE-TRANSFER.md)。

安卓安装前检查 APK 包名、版本、构建号、签名和最低系统要求，并由系统安装器完成覆盖安装。首次安装需要系统的「允许安装未知应用」权限。下载在前台更新弹窗内完成时会打开安装器；后台完成或关闭过弹窗时，重新打开更新弹窗点击「立即安装」。Windows 下载完成后点击「立即安装」，ZIP 包则打开所在文件夹。

安装校验期间关闭更新弹窗，会保留安装包，等待用户重新打开弹窗后点击安装。

下载完成或打开安装器都不会解除强制更新限制。此功能需要安装包含新功能的 App；旧版本仍按原有浏览器方式更新。
