# 天翼网页登录

Android 和桌面统一使用官网 `/web/login.html`，保留生成浏览器标识并打开 portal 登录 iframe 的完整流程；验证码、协议确认和提交仍由用户操作。浏览器和身份验证沿用同一账号隔离的桌面 UA，登录表单使用 400px 可缩放视口。

## Android 短信登录检测与滑块触摸

2026-11-27 根据 Android 2.4.0 短信登录后无法检测、滑块无法拖动的反馈，重新核对官网及云析公开源码。云析未提供天翼适配，其通用原生 Cookie 读取、接口校验及失败后继续等待的方式用于本轮流程对齐；没有复制其代码。

- 天翼每 1.5 秒采样原生 Cookie，自动检测和“检测登录”共用 `AccountLoginService.submitWeb`。沿用已有的 5 秒校验节流、同凭据失败后 10 秒重试、账号隔离及验证取消。
- 官网加载完成时立即发起原生 Cookie 检测，不等待表单布局脚本；已捕获的官方 Browser-Id 直接复用，首次脚本读取最多等待 2 秒。刷新或重新加载官方登录入口时取消旧检测与身份验证，清除旧标识，迟到结果不能写回或覆盖新一轮登录。
- 保留官网父页面、原始 iframe URL 和同一桌面 UA。整页改为手机 UA 会被官网转到 h5 授权流程，不能用这种方式解决滑块的鼠标事件与手指触摸不匹配。
- Android 原生 WebView 接收完整触摸序列；滑块脚本仅在 HTTPS `open.e.189.cn` 的 cloud web 授权页执行，嵌入时仅允许官方 cloud 直接 iframe。用户在官网滑块或拼图手柄上的真实单指拖动转换为连续鼠标事件，位置取用户触摸坐标；多指和系统取消时重置挑战。输入框、其他页面和官网原生手机事件分支不受影响，校验仍由官网执行。
- Android WebView 必须支持 `DOCUMENT_START_SCRIPT` 才能把脚本注入跨域授权 iframe。插件 1.1.3 的旧版降级只在顶层执行，不能保证 iframe 适配；明确检测到不支持时提示更新 Android System WebView 或切换账号密码登录，仍允许打开网页和手动检测。能力查询失败不阻断登录，诊断仅记录支持状态或错误类型。

本轮相关 Flutter 回归 148 项、生产浏览器脚本回归 46 项通过，覆盖原生 Cookie 检测不被挂起 JS 阻挡、真实坐标拖动、多指/取消、刷新丢弃迟到凭据、旧验证不保存账号、SSO 弹窗及其他网盘登录。使用官网下载的验证码模块进行本地隔离复现：修改前触摸不移动滑块，修改后能移动并交给原官网校验函数；未模拟校验成功。尚无连接的 Android 真机，未完成用户手机上的真实滑块及短信登录闭环。

## 同名登录 Cookie 与开源参考

2026-11-25 11:59 的用户日志已进入真实身份验证，并返回 `_TianyiSessionExpired`；这不能解释为完全未读到登录信息。只读真实会话复测确认：有效 `COOKIE_LOGIN_USER` 可独立通过身份接口；同一请求中错误的同名 Cookie 在前、有效值在后时，官网返回 `InvalidSessionKey`，顺序相反则成功。无效 JSESSIONID / LOGIN_USER 与 Browser-Id 缺失在这份会话中均未触发故障。因此，本次针对已证实的同名值遮蔽修复，尚不能断定用户 Android 真机失败只有这一原因。

原生 CookieManager 读取身份接口、cloud `/api/`、cloud `/` 时，先保留实际读取到的登录 Cookie 替代值，再进行通用合并；最多三份，仅在身份接口明确返回会话过期时核验下一份。每次沿用相同 UA、Browser-Id 和原请求取消范围，共用原有 15 秒验证上限。全部过期、服务错误、安全验证、取消或超时保留原账号，不通过另一份凭据绕过服务或设备验证。保存经过真实身份接口验证成功的 Cookie，清除临时候选字段；日志只记候选数量和序号，不记凭据。其他网盘的 Cookie 合并规则沿用原行为。

用户指定参考 [CYQawa/YunX](https://github.com/CYQawa/YunX)。检查其公开 master `cc9afe24c9409b239c361263b976f7aad77d1d9e`，平台与协议目录未见天翼登录实现。其 Android `QuarkLoginScreen.kt` 使用原生 `CookieManager.getCookie()`，`WebLoginAutoDetect.kt` 按 1.5 秒采样、5 秒校验节流、同凭据失败后 10 秒重试，经接口验证后保存；本项目复用已有同类流程并核对 Cookie 来源。这里只参考通用网页登录方式，没有移植云析的天翼适配。

## 官网登录成功但应用未检测到

2026-11-25 通过用户授权的真实短信登录，官网完成 cloud 域的 portal 回调并进入个人文件列表。回调生成 `JSESSIONID` 和 HttpOnly `COOKIE_LOGIN_USER`；网页的 `document.cookie` 仅能读取跟踪 Cookie，应用继续通过原生 CookieManager 读取身份接口可用的 Cookie。

真实会话通过当前 Dart `TianyiConnector`、`AccountLoginService` 和浏览器 UA 策略完成账号保存、容量读取与个人文件列表请求。带或不带 Browser-Id 都成功，单独的 JSESSIONID 则被官网拒绝。因此不能把缺少 Browser-Id 认定为所有检测失败的根因，也不放宽凭据检查或跳过真实身份验证。

本轮修正已核实的流程差异：

- 官网外层页会生成浏览器标识并写入 `udb_login` iframe 的 portal URL。入口保留该页，避免直接打开 portal API 跳过初始化；原有绑定脚本捕获官网使用的值。
- 短信切换脚本允许官方 cloud 顶层页直接嵌入的 `open.e.189.cn` web 授权 iframe，限定 HTTPS、准确域名、web 登录路径及 `appId=cloud`。其他父域、端口、嵌套层级和 WAP 表单不自动操作；不修改 iframe URL、不发送短信、不勾选协议、不提交登录。
- 官网外层登录页保持 400px 可缩放表单布局，账号回调及导航继续由官网完成。离开登录路由后恢复文件列表的桌面视口。
- Android 天翼登录依赖已有且被等待的登录前 Cookie 清理，关闭插件的额外 incognito 清理；插件 1.1.3 的该选项会启动未等待的全局 `removeAllCookies`。缓存仍禁用，登录成功、取消和失败的原有清理与账号归属检查保留。

本轮局部回归 234 项通过；生产浏览器脚本 42 项通过，其中官方 iframe 短信切换回归已确认修改前失败、修改后成功。真实官网脚本验收确认短信表单、原样浏览器标识和手机尺寸布局。私有 Dart 真实会话验证通过账号保存、容量和文件列表。尚未复现用户 Android 真机上的本次失败，以上不代表该设备已完成修复验收；需要新版真机结果与对应日志确认。

## 短信登录后会话失效

2026-11-24 用户提供的 Android 日志显示：完成短信登录后，身份接口返回 `_TianyiSessionExpired`。匿名检查官网确认，旧 WAP 入口将短信会话回调到移动域，客户端随后在 cloud 域校验 portal 身份；混读 mobile、h5、web 路径的同名 Cookie，并切换网页与校验 UA，可能提交不匹配的会话。

- 当时入口改为 `cloud.189.cn/api/portal/loginUrl.action`，官网使用 cloud 域的 `/api/portal/callbackUnify.action` 完成登录；当前入口进一步保留上文的官网外层初始化。
- 当时自动切换短信表单仅限官方顶层 web 登录页且 `appId=cloud`，每个步骤只点击一次；当前增加上述官方直接授权 iframe 支持。
- Cookie 仅从身份接口地址、cloud `/api/` 和 cloud `/` 读取，优先保留身份接口收到的 Cookie，包括 HttpOnly；其余旧来源保留在登录清理范围。
- 允许回调和落地页面正常导航，由原有加载、历史更新和轮询完成检测。真实身份接口仍决定成功或失效，失败不覆盖已有账号，更新 Cookie 后可以重试。

## 检测等待与取消

此前用户还反馈登录后一直停在检测。账号身份验证后的容量请求，以及网页登录验证、清理 Cookie 和页面跳转中的脚本读取，都需要独立等待上限；以下约束继续保留。

- Cookie 的独立路径并行读取。首次网页浏览器绑定读取单独设 2 秒上限，已捕获值不重复等待脚本；页面脚本不可用时仍可验证原生 Cookie。
- 天翼单轮网页登录信息读取上限 12 秒、账号验证上限 15 秒。超时释放检测状态，显示重试提示；账号验证超时取消所属请求，不提交迟到结果。
- 身份验证成功后的容量读取最多等待 3 秒，超时取消独立请求，仍保存已验证的账号。常规账号刷新继续读取容量。
- 登录前后 Cookie 清理等待最多 3 秒。登录前清理失败仍阻止打开旧会话；登录后清理失败记录诊断后退出登录页。
- 用轮询编号识别检测状态，页面重建或旧异步回调不能把新的检测锁住。
