# 夸克普通上传分片失败

用户反馈：普通上传单个约 430MB 文件，2026-11-20 14:17:58 的 `upload.file.failed` 日志提示“文件上传失败（HTTP 400）”，阶段为 `uploading`。

堆栈定位到分片 PUT 请求，尚未进入文件合并。旧实现丢弃了存储服务的错误码和响应信息，无法仅凭这条日志确认原始原因。文件大小本身不超出当前分片实现支持范围。

## 调整

- 每次重试重新获取该分片的上传签名、日期；原实现的网络重试重复使用原签名。
- 从上传预处理响应的服务器时间开始计时，减少设备时间偏差对签名的影响；明确的时间错误响应可更新校准值。
- 上传内容类型优先使用网盘预处理回执，签名和实际请求保持一致。
- 采用网盘返回的 `part_thread` 建议，最多保留原来的三个并行分片；不调整下载连接数。
- 明确的过期、时间、签名错误及暂时不可用响应允许在同一上传任务内重传同一分片，最多三次；未知 HTTP 400 直接失败。
- 服务器报告分片已存在时，仅在回执 MD5 与本地相同范围一致的情况下采用已有分片。
- 任意分片失败都不会进入合并；合并请求的结果不明确时不会自动重放。
- 新增 `upload.storage_rejected` 诊断，记录 HTTP 状态、存储错误码、分片序号、数量、大小和尝试次数。提示保留有格式限制的错误码，不记录完整响应、签名或账号凭据。

相关实现：`lib/data/providers/uploads/quark_upload.dart`、`lib/data/uploads/upload_io.dart`。

## 验证范围

108 项相关测试通过，静态检查无问题。新增测试覆盖 430MiB 的 108 个分片范围、重试重新授权、服务端并发建议、服务器时间、内容类型、失败停止、日志字段和不重复合并；同时回归上传队列、文件夹上传、其他网盘协议及 S3。

本次使用模拟存储服务，没有实际上传用户的 430MB 文件，原始 HTTP 400 的具体根因仍待新版错误码或完整日志确认。未编译、未提交或发布。

参考 OSS 分片语义：<https://www.alibabacloud.com/help/en/oss/developer-reference/uploadpart>。

## 后续上传准备调整（2026-11-23）

对照 [OpenList 夸克/UC 上传实现](https://github.com/OpenListTeam/OpenList/blob/7c26f1012c2951441233dce4ef309753fc76165d/drivers/quark_uc/driver.go#L132)，将整文件 MD5/SHA-1 计算移到创建上传会话之前。大文件或较慢的文档提供器读取不会再消耗远端上传任务和凭据的有效期；本地读取失败或校验中取消时也不会创建远端上传会话。已有中转摘要继续复用。

同一分片的授权请求也纳入既有最多三次的尝试预算。申请签名时遇到可重试网络错误会重新申请，耗尽后停止其他分片且不合并；不新建整个上传任务，也不扩大最终合并请求的重试范围。

该调整消除了可复现的时序风险，不能据此认定历史 HTTP 400 一定由凭据过期引起。上传页面也包含跨盘传输，来源下载准备阶段的分享 token 错误需要按[跨盘传输](CROSS-DRIVE-TRANSFER.md)的来源恢复路径处理，不属于分片 PUT 失败。
