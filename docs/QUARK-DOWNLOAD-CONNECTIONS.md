# 夸克下载连接数实测

2026-11-13 使用备份中的夸克普通账号（接口确认为 `NORMAL`），在当前 Windows 主机及网络上，用应用自带 Gopeed 1.8.1 内核比较单文件、单视频和三个视频同时下载。

默认值：夸克直链 `quark_route_1` 从每任务 512 调整为 **128**。快传 `quark_route_2` 保持 **64**。同时下载默认仍为 3 个任务。

## 测试方法

- 普通账号原有文件没有视频，提供的分享视频约 50 GB，超过账号可用空间；本轮没有转存它。
- 上传临时 256 MiB 随机普通文件，以及 539,002,600 字节（约 514 MiB）的 MKV。视频由仓库播放样片循环、无损封装生成，上传前通过 FFmpeg 解码验证。
- 三任务使用三个独立云端文件条目，内容相同，模拟同一 CDN 上多个视频同时下载；本轮不是三个不同影片或三个不同 CDN 的测试。
- 直链为常规账号 `file/download` 下载，包括视频下载；快传独立获取链接比较，没有改变普通下载的授权路线。
- 共完成 25 组测速，每组约 18 秒；每约 250 ms 采样，按 3–18 秒内真实可读分片字节增量计算速度，同时保留 3–12 秒窗口、任务各自速度、活动连接、首批数据时间、CPU、内存及暂停耗时。
- 每组暂停后，逐字节核验所有已完成分片与原始文件一致。统计的是内核 `readableRanges`，不以预分配文件长度代替实际下载量；部分下载不代表整个文件完成。
- 分档顺序打乱；三任务对 32、64 和 512 做了第二次测量。测速没有任务失败，所有实际落盘分片核验通过。

## 直链结果

速度单位 MiB/s；三任务总速度包含任务各自速度。无数据表示在本组约 18 秒内没有收到可读文件内容。

| 每任务连接数 | 单视频 | 三视频合计 | 三个任务分别 | 实际活动连接峰值（三任务） |
| ---: | ---: | ---: | --- | ---: |
| 8 | 0.227 | 0.688 | 0.230 / 0.229 / 0.228 | 24 |
| 16 | 0.381 | 1.367 | 0.453 / 0.456 / 0.458 | 48 |
| 32 | 0.811 | 2.487 | 0.855 / 0.787 / 0.845 | 96 |
| 64 | 1.592 | 4.540 | 1.484 / 1.522 / 1.535 | 192 |
| 128 | 3.080 | 4.524 | 1.397 / 1.673 / 1.454 | 384 |
| 256 | 4.711 | 4.454 | 2.277 / 2.177 / 无数据 | 512 |
| 512 | 4.536 | 4.343 | 4.343 / 无数据 / 无数据 | 512 |

三任务复测：

| 每任务连接数 | 合计 | 三个任务分别 |
| ---: | ---: | --- |
| 32 | 2.738 | 0.909 / 0.917 / 0.912 |
| 64 | 4.432 | 1.526 / 1.458 / 1.448 |
| 512 | 4.427 | 无数据 / 4.427 / 无数据 |

普通文件单任务：8、32、128、512 连接分别为 0.201、0.790、3.764、5.410 MiB/s。

128 是兼顾单视频速度和默认三任务的选择。64 在三任务中的总速度相近且开销更低，但单视频速度约为 128 的一半。256 的单视频更快，但三任务已有一个拿不到数据。512 没有提高本轮多任务总速度，并重复出现仅一个任务能下载的情况。

这与现有内核的同主机 512 连接槽相符：三个同主机任务各申请 512 时，某个任务可能占满所有槽；三个任务各 128 的需求为 384，均能获得连接。内核全局另有 768 的上限。本次改默认预设，没有修改连接调度器；更高的同时下载数或用户手动设为 256/512，仍可能碰到连接槽等待。

单视频 128 的进程 CPU 为单核的 8.6%，512 为 17.1%；三任务 128 为 11.8%，512 两次为 13.8% / 13.3%。同一内核连续运行时内存会受前组缓冲及垃圾回收影响，不按单组峰值直接推算手机节省比例。

## 快传结果

三个视频同时下载，8、64、16、32 连接的总速度分别为 5.747、5.802、1.410、2.768 MiB/s。8 与 64 在前两组很接近，但随后吞吐明显变化；快传没有完成交替复测，证据不足以认定 8 比 64 更合适，因此保留 64。

## 生效与验证范围

- 未手动覆盖的夸克直链新任务采用 128，包括普通文件和视频；跨盘中转沿用共享下载配置，也会采用该预设。
- 手动连接数、跟随全局选项及备份恢复继续有效。已有下载任务保留创建时记录的连接数，不重分已有断点。
- 更新设置、普通文件及视频路线传递、连接数展示的回归断言，同时核验下载准备和跨盘下载。
- 相关 5 个测试文件共 99 项通过；随后补强手动设置恢复和旧夸克任务续传断言，相关 59 项再次通过。改动 Dart 文件静态检查及差异空白检查通过。
- 这轮是一个普通账号、本机网络、Windows 内核和小于 1 GiB 样片的短时测试，不能推算手机耗电、超 1 GiB 文件、长期限速或其他网络下的绝对速度。
- 追加较长对照在重新上传样片的准备阶段遇到 TLS 连接错误，没有产生追加测速数据，也没有用于默认值判断。
- 两轮临时云目录均已删除并查询确认不再出现在根目录；未清空账号回收站。隔离下载内核已退出，下载分片及本地大样片已清理。脚本和无凭据的完整采样报告保留于 `.local/quark-download-tuning-20261113/`，不进入发布包或提交。
