## 已补充的回退

Windows 原先缺少 Android 已有的“兼容硬解模式”。现在播放设置也提供该开关并沿用已有持久化设置：

- 关闭：`hwdec=auto`，保持现有默认。
- 开启：`hwdec=auto-copy`，只尝试拷贝硬解，避免直接导入解码器表面；设备不支持时仍由 mpv 回退软件解码。
- 切换时沿用播放器原有重载机制，保留当前位置及播放/暂停意图。独立视频小窗继承相同解码策略；Android 保持原来的 `mediacodec-copy` 策略。
- 日志补充请求硬解模式、兼容设置、底层硬件像素格式和色彩参数；色彩参数直接取现有 `VideoParams` 状态，不增加周期 FFI 读取。

拷贝硬解可能增加内存带宽和 CPU 开销，因此默认不启用。没有裁剪视频底边，也没有把 4K 全局改为软件解码。

参考 [mpv hwdec 手册](https://mpv.io/manual/stable/#options-hwdec)：`auto-copy` 支持所有视频输出。手册与 [上游问题 #10719](https://github.com/mpv-player/mpv/issues/10719) 也提到 D3D11 直接采样的边缘 padding 风险，但 `d3d11va-zero-copy` 只对 `gpu-api=d3d11` 生效，本项目使用 ANGLE/OpenGL，不能直接把该问题的原因套用到这里。

## 验证与仍需确认的内容

新增原生测试用真实 mpv handle 确认 `auto-copy` / `auto` 属性切换，软件模式不会被兼容开关重新启用硬解；平台纹理由夹具代替，不等于验证了实际 GPU 画面。界面测试确认 Windows 开关可用、设置持久化以及暂停进度保持。

最终验证：26 项原生与解码策略测试、81 项播放/恢复/小窗回归和 116 项播放器界面测试全部通过，相关 Dart 静态检查及差异检查通过。三张设置截图经检查后更新基线，变化为兼容模式选项。

需要在反馈电脑用同一文件、同一位置依次对照默认硬解、兼容硬解和软件解码。只有兼容/软件模式能消除绿线时，才能进一步缩小到硬解互操作链路；若三种模式都有，继续核对原始媒体与实际渲染截图。本轮未声称绿线已在反馈电脑消失，未编译发布。
