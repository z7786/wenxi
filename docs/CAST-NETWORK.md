# 电视投屏本机地址修复（2026-11-15）

## 依据与根因

`logs/投屏失败问题报告.md` 记录 15 次连接在几十毫秒内以 `SocketException` 失败，手机地址为 `192.168.5.7`，电视为 `192.168.5.6`。报告没有原始 errno，因此仅凭旧日志不能区分 TCP 连接和本机监听失败。

已核对项目使用的 Dart SDK 实现：`Socket.connect(host, port)` 中的 `Socket.address` 返回构建 socket 时传入的地址，也就是连接目标，并不能用来读取系统选择的本机出口 IP。原 `CastSession._route` 返回该值，随后 `ExternalPlaybackStream.lan` 将其用于 `HttpServer.bind`。真实电视不与本机共用 IP，会在绑定时报地址不可用；之前的模拟电视与本机共用一个 IP，未覆盖这种情况。

旧本地文件投屏还会提前返回 `prepareMedia`，不产生 `cast.source_prepared`，所以缺少此事件本身不代表视频一定未准备好。

## 修复

- 按电视地址族枚举实际分配给本机的局域网地址；按地址相似度和网卡类型排列候选。地址相似度只用于排列，不能代替实际可达性判断。
- TCP 探测通过 `sourceAddress` 显式绑定本机候选，连接成功后直接使用这个已知地址。首个地址不可达时尝试其他地址，总探测时间保持最多 5 秒、最多 8 个候选。
- 中转继续仅监听选中的本机地址；不依赖 `Socket.address`，也不扩大到所有接口。局域网 URL 不使用回环地址，回环地址仅用于测试接收器。
- 失败日志记录 `stage`、原始异常类型及 socket 的 `errno` / `os_error`；本机地址记录散列，错误文字仍经已有脱敏器处理。
- 增加 `cast.route_selected` / `cast.relay_started`，本地文件也记录 `cast.source_prepared`，方便区分地址选择、监听、本地文件访问、取链、电视控制失败。
- 本机监听失败提示检查本机网络；控制失败和视频源失败分别提示。失败清理继续释放中转及平台保持运行状态，保留原本的播放进度、恢复本机和重连行为。

## 验证范围

协议回归涵盖模拟电视独立 IP、本地 MKV 分段读取、超过 5 GB 的 Android `content://` 文档读取、HEAD 不读文件、尾段范围、IPv6 / CGNAT 候选、多个网卡、无局域网、错误码与隐私脱敏、本机播放恢复和连接失败文案。原有投屏协议、暂停、定位、切集、取消、重连及播放器界面测试继续执行。

测试用模拟 DLNA 接收器和 Android 文件通道，没有连接反馈用户的小米电视；电视解码具体 MKV、音轨及字幕的兼容性仍需该设备验证。此修改没有转码，也没有变更 HLS / DASH 支持范围。

## 13:56 日志中的播放指令失败

最新 `文析助手-logs-2.3.1-231-1794722182301595.zip` 来自 vivo V2243A / Android 13，生成于 2026-11-15 13:56:22。归档中 5 项文件的长度和 SHA-256 均通过核验。13:55:41 已完成百度视频取链、本机地址选择、中转启动及 415015340 字节的 MP4 源准备，随后在 `play` 阶段记录 `HttpException` 并关闭会话，没有成功连接事件。这次失败不能归因为之前的本机监听地址，也不能用它确认电视已出画面后的声音或字幕问题。

旧日志没有 HTTP 异常信息、状态码或请求读写阶段。只能确认控制响应异常，无法据此确定电视是否已经执行 Play，或是否由连接复用导致。模拟接收器已复现复用连接被关闭、执行指令前断开、执行指令后响应丢失，以及 HTTP 响应被截断时旧流程直接退出。

### 控制兼容处理

- 设备描述和 SOAP 请求设置 `persistentConnection = false`，发送 `Connection: close`；每次重新建立控制连接，视频和字幕中转流不受影响。
- 保留 SOAP 的明确错误码处理；HTTP、socket、超时及无效控制响应带上动作、请求阶段和状态码。异常文字只记录脱敏后的短信息，不写完整地址、凭据或响应内容。
- 仅 Play、Pause 和绝对时间 Seek 使用有界确认。响应丢失后等待 300 毫秒，使用同一总计最多 3 秒预算读取 `GetPositionInfo`、必要时 `GetMediaInfo`，并核对本会话中转地址，再读取 `GetTransportInfo`。
- 电视确认已经执行目标操作时接受该结果，继续原进度及暂停意图。只有当前视频仍属于本会话、没有回报播放错误且操作尚未完成时，才允许第二次发送；第二次响应仍异常时再次确认，之后返回失败。
- 缺少可核验的视频地址时不判定成功，也不盲目重试。电视已切换其他内容时放弃控制权，后续关闭不会 Stop 他人的视频。明确的非成功 HTTP 状态与 SOAP 错误不会作为响应丢失处理；原 SOAP 701 就绪重试仍保留。
- SetAVTransportURI、未知写入和音量操作不自动重发。取消、换源与会话关闭继续等待已发送指令，确认和重试各步检查取消状态，保持 Stop 之后不再迟到 Play，失败时恢复本机或原投屏会话并释放源引用。
- 新增 `cast.control_failed`、`cast.control_probe_failed`、`cast.command_confirmed`、`cast.command_retry`。连接和轮询失败日志包含 `action`、`request_stage`、`http_status`、脱敏 `http_error`，或系统 errno，便于下一份日志确认具体故障。

参考：[Dart persistentConnection](https://api.dart.dev/stable/latest/dart-io/HttpClientRequest/persistentConnection.html)、[Dart abort](https://api.dart.dev/stable/latest/dart-io/HttpClientRequest/abort.html)。`abort()` 在请求响应 future 已完成后无效，不能将原来的 finally abort 直接当作已确认根因。
