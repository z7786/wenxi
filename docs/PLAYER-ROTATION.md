# 手机播放旋转优化（2026-11-15）

## 已确认的代码路径

播放器每次布局变化会将当前窗口尺寸提交给后端。Android 根据该尺寸缩放视频纹理；横竖屏互换时，同一视频的纹理大小通常不同。内置的 Android GPU 输出每次改变纹理大小会依次设置 `vo=null`、`android-surface-size`、`wid` 和 `vo=gpu`，重新建立视频输出和硬解表面互操作，4K/60 fps 等视频更容易出现明显停顿。这里只确认了代码中存在额外重建，尚未在反馈手机上测量具体时长。

运行中的手动方向切换还会设置 `_rotationPending`，临时覆盖黑色画面、隐藏字幕并显示加载动画；平台不接受方向请求时，该状态最长保留 1.2 秒。尺寸更新的旧防抖逻辑也有两个问题：同一待处理尺寸被重复通知推迟，快速转回当前尺寸时未取消旧任务。

## 调整

- Android 手机的普通视频界面取当前屏幕与横竖互换屏幕中较大的渲染需求，仍保持片源比例、物理像素和片源分辨率上限，缩放及原有持续丢帧降档继续生效。因此同一片源单纯旋转屏幕时无需重新设置纹理大小。
- 视频继续沿用同一播放器与 Flutter 视频节点，画面比例及字幕布局跟随当前窗口变化；旋转不重新取链、跳转进度、暂停或重开播放。
- 播放和暂停中的方向切换不增加黑色遮罩、加载动画或隐藏字幕；匹配新方向的首个布局帧直接完成方向等待。首次打开和切换新片源仍保留原先的布局准备与拒绝旋转的超时保障，网络缓冲仍正常显示。
- 去重相同目标尺寸，取消过期防抖任务，原生输出更新顺序执行。更新已开始时，后续只应用最新目标；失败等待下一次布局或状态通知再重试，退出时取消未开始的工作。
- 画中画按小窗口实际尺寸渲染；Windows、macOS、Linux 和电视保持原来的窗口计算。iOS 没有走 Android 纹理尺寸更新，但共用运行中旋转不遮盖画面的调整。

## 取舍与验证

横屏正常播放时所需渲染尺寸不增加。竖屏观看横向视频时会保留适合横屏的纹理，GPU 和纹理内存开销可能比仅按竖屏缩小更高；它受屏幕、片源及原有持续丢帧降档限制，没有全局提高到原始 4K，也没有强制软件解码。

保留 Android GPU 输出真正改变尺寸时的重建流程。当前打包的 libmpv 为 v0.36.0，其 Android EGL context 在 `android_reconfig` 中重设 swapchain，`android_control` 返回 `VO_NOTIMPL`；直接删除 `vo` 重建存在尺寸不更新和画面异常风险。

参考：[mpv Android surface 参数](https://mpv.io/manual/stable/#options-android-surface-size)、[v0.36.0 Android EGL context](https://github.com/mpv-player/mpv/blob/v0.36.0/video/out/opengl/context_android.c)。

自动测试覆盖横竖屏共用尺寸与画质边界、重复通知、快速转回、正在更新时再次旋转、失败重试、切换片源、销毁、桌面及画中画尺寸；界面测试覆盖视频节点复用、播放/暂停意图、字幕、进度、首次自动播放、拒绝方向请求及连续点击方向切换。测试中的 Surface 是夹具，不能代替 Android 真机 GPU 性能测量。
